**Problem:** `match packed { None => window(..), Some(p) => restart_window(..) }`
occurs at `M3:674-683`, `M3:1899-1912`, `M3:1913-1918` and `mamba2.rs:857-866`. Each

**Direction:** One reader, built once per call from the padding and the resets. It
gives the last `L` real positions of a stream, from its carry and origin. 5 fields in
3 families read through it. It keeps the plain `narrow` when no row has padding,
because `cat` and gather cost memory.

**Also:** `src/mamba3/mamba3.rs:1647` has a private `Packed`, with the name of
`burn_stack::utils::Packed`. Give it another name in this work.

### Agent brief

**Category:** enhancement

**Summary:** One row-end reader, `RowEnd`, does each read of a "last samples" cache
field in the three families. The private Mamba-3 `Packed` becomes `PackedCall`.

**Current behaviour:**

- Each family reads a cache field that keeps the last samples of a row at the row end
  of that row. Examples are a conv window, the tap FIFO and a positive carry. Under padding,
  this read is a gather at an offset for each row (`padding::window`).
- In a packed call, the entries from before the last segment come from the origin
  (`packing::last_origin`, `packing::restart_window`).
- Four sites repeat the same steps. Each one selects the origin, does a `Tensor::cat`,
  then does `match packed { None => window, Some => restart_window }`. The sites are:
  - the conv window of Mamba-2,
  - the `ln Λ` and `c` carries of the Mamba-3 positive systems,
  - the `B` and `x` of the tap FIFO,
  - the decay of the FIFO slots.
- The conv window of Mamba-1 does a part of these steps.
- A site that gives the incoming field in place of the origin reads a stale carry with
  a correct shape. Only the packed tests show this mistake.
- The Mamba-3 plant frame carries the row end (`end_b`) and the packed call (`Packed`)
  as two separate fields. The private `Packed` has the name of
  `burn_stack::utils::Packed`.

**Desired behaviour:**

- The code builds one `RowEnd` for each call, from the padding and the resets of the
  call. It also knows the positions of one token: `u` for Mamba-3, 1 for Mamba-1 and
  Mamba-2.
- Each row-end read of the three families goes through `RowEnd`. These reads are of
  the two conv windows, `ln Λ`, `c`, the tap FIFO and the decay of the FIFO slots. No
  site matches on the padding or on the resets for this read.
- A read gives the last `width` samples of each row before its row end, along one
  axis, from `[start | new samples]`. For a row with a reset in the call, `start` is the
  origin field. For other rows, `start` is the incoming field.
- In a packed row, each entry from before the start of the last segment comes from
  `start`.
- A read in a call with resets requires the origin field. If the origin field is
  missing, the read panics with a message that gives the cause.
- A read is one `narrow`, with no gather, when both of these conditions are true:
  - No row of the call has padding.
  - The call has no resets, or `width` is not more than the positions of one token.
- When the new samples hold at least `width` positions, that `narrow` reads the new
  samples alone, with no `cat`.
- The Mamba-3 plant frame carries one `RowEnd` in place of `end_b`. `save_tap_slots`
  and `positive_tail` read through it.
- The private Mamba-3 `Packed` is `PackedCall`.
- The docs say "row end" where they now say that a row reads a field "at its own end".
- The outputs, the caches and the gradients do not change.

**Names:**

- `crate::row_end` and `RowEnd`: the new module and the reader. Its private helpers do
  not use "window" or "restart" in their names.
- `padding::real_end_b` goes into `RowEnd`, with a name that says "row end".
- `padding::window`, `packing::restart_window` and `packing::last_origin` become private
  helpers of `crate::row_end`, or they go. No other module calls them.
- `Packed` (Mamba-3, private) becomes `PackedCall`.

**Tests:**

- Add a test of `RowEnd` in the seam "Mechanism against its direct form" of
  `docs/agents/testing.md`. It compares each read with its direct form: a `narrow` on
  the host for each row, of `[start | samples of the last segment]`, at the row end.
  Its cases:
  - no padding and no resets (the `narrow` path),
  - padding,
  - a reset whose last segment is shorter than `width`,
  - a last segment that holds only padding,
  - a call that is shorter than `width`.
- Add a `should_panic` test: a read in a call with resets and no origin field.
- Change no other test. Do not change an expected value or a tolerance.

**Constraints:**

- The bench paths have no padding and no resets. They keep one `narrow` for each read,

### Implementation state

> *This was generated by AI during implementation.*

`crate::row_end` holds `RowEnd`. Its module header holds the mechanism, the index math and
the condition for one `narrow`. `RowEnd::new(pad_bs, resets, micro_steps)` takes
`resets = (reset_bn, chunk_len)`. `micro_steps` is the positions of one token: `u` for
Mamba-3, `1` for Mamba-1 and Mamba-2. Each read goes through one of two methods:

- `read(samples, axis, width, incoming, origin)` reads a cache field: the two conv
  windows, `ln Λ`, `c`, and the `B` and `x` of the tap FIFO. In a call with resets, it
  panics before the choice of path if `origin` is `None`.
- `read_after_zeros(samples, axis, width)` reads the decay of the FIFO slots.
  `save_tap_slots` calls it only for `lag > 1`, because at `lag = 1` the one slot has no
  decay.

The private helpers are `row_end_b`, `last_segment_start_b`, `origin_where_reset` and
`gather_rows`. `padding::real_end_b`, `padding::window`, `packing::last_origin`,
`packing::last_start_b`, `packing::restart_window` and the two `Segments` methods that
called them are gone.

1. The three `rg` checks find what the criteria say.
2. The File Map has a `row_end.rs` line. The seam row "Mechanism against its direct form"
   lists `src/row_end/tests.rs`.
3. `./scripts/check.sh` passes.

5. The version in `Cargo.toml` did not change.

**Changes outside the list of the brief:**

- `src/mamba3/plant_frame/tests.rs` changes one line. Its `PlantTail` literal sets
  `row_end: RowEnd::new(None, None, u)` in place of `end_b: None`, because the field changed.
  That reader takes the same `narrow` path. No expected value or tolerance changed.
- `helpers::tail_decay` does not `narrow` an input of exactly `lag` positions. Without
  this, a FIFO read at `lag ≥ 2` does two `narrow`s. Because of it, the Mamba-3 `step` at
  `u ≥ 2` has one full-range `narrow` less. The values do not change.
- With no padding, Mamba-1 and Mamba-2 now `narrow` the conv input before the `cat`, not
  the padded `cat`. A call with `sequence < conv_kernel` adds one `cat`. No bench path has
  such a call.

**Review findings that did not change the code:**

- The pair `(reset_bn, chunk_len)` is `packing::Segments` without `start_bs`. Mamba-2 does
  not build `Segments`, because `start_bs` costs ops that it does not need.
- `positive_tail` takes the origin carries from `packed`, because the tropical register
  needs `packed` for its segment starts. `save_tap_slots` takes the incoming and the origin
  FIFO as arguments.
- `row_end_b` and `last_segment_start_b` have the same shape of ops (arange, mask, max).
  They stay two functions, because they give two different positions.
- `save_tap_slots` keeps its name, as this brief names it. The name uses "tap slots" for
  the whole FIFO, which `GLOSSARY.md` avoids. A rename is a follow-up.

**Benches:** none. Each read on a path with no padding and no resets is one `narrow`, as
before. At `lag = 1`, the decay of the FIFO has no op, as before.
