# 03: One recompute node

Status: resolved

Blocked by: `../burn-stack/.scratch/arch-review-backlog/issues/06-recompute-node.md`

From the architecture review of 2026-11-03. Line numbers are those of commit
`42ca3d0e`. Not compiled.

**Files:** `src/mamba2/ssd/serial_recalculated/backward.rs:29-351`,
`src/mamba3/{double,single}_ssd/ssd/serial_recalculated/backward.rs`,
`../burn-stack/src/utils/combined_grad.rs:24-76`.

**Problem:** The three `backward.rs` hold 1,040 lines and no math. Normalised, 180 of
190 double-SSD lines occur in single-SSD, and 139 in Mamba-2. One input costs about
20 mentions. The author keeps `prepare([...])`, `ops.parents`, `State` and the const
`N` in order by hand. `47c7dd10` (one Burn interface change) edited all three.

**Direction:** One generic node module owns the prepare step, both `OpsKind` arms,
the pair flatten and split, and the gradient consume and register. Each plant keeps
its inputs, constants, inner forward call and `combined_backward` call.
`combined_grad` folds into the module.

**Open:** Which crate owns the module. Only these three files call `combined_grad`,
but burn-stack ADR-0001 names it as plumbing. Split this ticket by repo at triage.

**Cost:** `Backward<B, const N>` needs `Send + Debug + Sized + 'static`. A zero-size
plant type fits. A closure does not, because it is not `Debug`. Static dispatch adds
no run cost. The `UnTracked` arm runs `float_cat` with no gradient to serve, and one
module can remove that copy.

ADR-0007 is not affected, because the node holds no math.

### Agent brief

**Category:** enhancement

**Summary:** Move the three SSD recompute backwards to the recompute node of burn-stack.
This brief replaces the **Direction**, the **Open** point and the **Cost** above.

**Current behaviour:**

- The `Autodiff<B, C>` impls of `Mamba2BackendExt`, `Mamba3DoubleSsdBackendExt` and
  `Mamba3SingleSsdBackendExt` hold 1,040 lines and no math.
- One differentiable input costs about 20 mentions.
- Each impl computes every `shape_*` and `flat_len_*` value by hand.
- 22 reshapes change a saved input to the shape that it has.
- `State` holds `restarts`, and on single-SSD the seeds, as `Option`.

**Desired behaviour:** Each impl is one call of `recompute_pair` and one `RecomputeOp`
impl at module level. The outputs, the final caches and the gradients of every pathway
and SSD path stay the same.

**Key interfaces:** `RecomputeOp`, `recompute_inputs!` and `recompute_pair` come from
the burn-stack ticket.

| Op | `N` | Named inputs | `Extra` |
|---|---|---|---|
| Mamba-2 | 8 | `x`, `dt_discretized`, `b`, `c`, `d`, `initial_state`, `a_decay`, `origin` | `keep_bn`, `resets` |
| Double-SSD | 6 | `v`, `da`, `b`, `c`, `initial_state`, `origin` | `read_stride`, `keep_bn`, `resets` |
| Single-SSD | 9 | `v`, `da`, `b`, `c`, `gamma`, `scale`, `initial_state`, `seed`, `origin` | `read_stride`, `siso_specialization`, `keep_bn`, `resets`, `seeded` |

The field names keep their shape suffixes.

**Constraints:**

- `keep_bn` goes in `Extra`, because it takes no gradient and is not a parent.
- `origin_bhpr` and `seed_bnhpr` stay parents. Their placeholders hold one element, so
  the node saves them at no real cost.
- The backward of an op passes `origin` to `combined_backward` only when `resets` is
  `true`. It passes `seed` only when `seeded` is `true`. Each returns `None` otherwise.
- The backward of an op wraps the saved inputs with `F::new` and does no reshape.
- The backward of an op takes its inputs by value, and it holds no extra clone. A clone
  that a caller holds raises the GPU peak.
