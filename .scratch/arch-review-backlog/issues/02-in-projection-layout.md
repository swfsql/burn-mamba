# 02: One in-projection layout

Status: resolved

Blocked by: None

From the architecture review of 2026-11-03. Line numbers are those of commit
`42ca3d0e`.

**Files:** `src/mamba3/mamba3.rs:501-577,1276-1294,1316-1386`,
`src/mamba3/double_ssd/double_ssd/mod.rs:138-181,678-733`,
`src/mamba3/single_ssd/single_ssd/mod.rs:180-225`.

**Problem:** The order of the channel groups is in code at 6 sites: 3 splits,
`split_positive`, `d_in_proj_tail` and `muon_projections`. It is in prose at 7 more.
`Δ, A, λ, μ, noise, a, b` all have width `u·nheads`, so a swap gives no shape error.
A zero-width group "would silently vanish" (`D:146-149`). `assert_plan_fits` checks
only width sums. A grep found no test that ties the Muon order to the split order.

**Direction:** One ordered description of the channel groups, derived from the
config: name, width, axis, optimizer, head or tail. The widths, the Muon plan and a
split into named streams read it.

**Tests:** Each group reaches its stream. The Muon names match the split.

**Cost:** The same tensor ops. `split_into` has a fixed arity, so optional groups
keep `narrow`.

### Agent brief

**Category:** enhancement

**Summary:** Put the channel groups of the Mamba-3 in-projection into one table. The
widths, the Muon plan and the split read this table. This brief replaces the
**Direction** and the **Cost** above. The site counts above are older than ticket 01.

**Current behaviour:**

- Two places hold the order of the groups: `split_in_proj` with `split_positive`, and
  `muon_projections`. Seven places in the docs repeat the layout.
- Three places hold the presence condition of each optional group: its
  `*_channels_total` method, `d_in_proj_tail` and `muon_projections`.
- No test ties the Muon plan to the layout. The tests check membership, counts and
  the width sum. A swap of `rotation` and `kalman_noise` in `muon_projections` should
  pass all the tests. Muon then updates the noise channels, and the fallback
  optimizer updates the rotation channels.

**Desired behaviour:** One table holds the order, the width, the axis, the optimizer
and the head-or-tail place of each group. A new optional group costs one table row
and one `InProjStreams` field. The outputs, the final caches and the gradients of
every pathway and SSD path stay the same.

**Key interfaces:** `src/mamba3/in_proj_layout.rs` holds the table. Its items are
`pub(crate)`.

- **An entry** has a group key, a name, a width, the axis, the optimizer and the
  head-or-tail place. The key is an enum with one variant for each group. The width
  counts the channels of one micro-step, or of the token for a per-token group.
- **The table** lists the entries of the groups that the block projects, in layout
  order. Each entry has a width above zero. `Mamba3Config` and `Mamba3` hold the same
  scalars, so each one can build the table.
- **`d_in_proj` and `d_in_proj_tail`** sum the widths of the table.
- **`muon_projections`** makes one `SubProjection` for each micro-step of a group.
  Under `Mamba3Untied::InProjTail`, the tail entries go to `in_proj_tail.weight`.
- **`split_in_proj`** calls `split_with_sizes` once, with the widths of the table. It
  takes each part by its group key. `InProjStreams` keeps one field for each stream.

**Constraints:**

- The order of the groups does not change. Some tests edit a weight by position, for
  example `append_dead_sub_projections`.
- The presence conditions do not change:
  - `lambda_raw`: `tap_pattern.has_beta_tap()`
  - `mu_raw`: `tap_pattern.has_two_taps(u)`
  - `rotation`: `num_rotation_channels > 0`
  - `kalman_noise`: `gain.projects_noise()`
  - `tropical_a` and `tropical_b`: `tropical.is_on()`
- `d_in_proj`, `d_in_proj_tail` and `muon_projections` stay public.
- `documented_layout` in the split tests does not read the table. It stays the
  expected value.

**Deletions:** Delete the five `*_channels_total` methods, `split_positive` and
`split_trailing`. Only the split and the tests call them. A test that needs the width
of a group reads the table.

**Names:** Old configs, records and tensor data do not have to load under the new
code (user decision). So a rename needs no migration. This permits a rename, but it
does not request one.

- Each tensor keeps its descriptive name and its shape suffix (`CLAUDE.md`, Notation).
  The fields of `InProjStreams` do not change.
- Do not shorten a name. A new name must describe its value as well as the old name.
- One group has one name in the table, the Muon plan, the doc of `Mamba3::in_proj` and
  `documented_layout`. Use these names, in layout order:

  `z`, `x`, `b_raw`, `c_raw`, `dd_dt`, `dd_a_raw`, `lambda_raw`, `mu_raw`, `rotation`,
  `kalman_noise`, `tropical_a`, `tropical_b`

- Each of these names is in the code today. Most are the stem of the stream field.
  `rotation` and `kalman_noise` are the longer names of the Muon plan.
