## Agent Brief

**Category:** enhancement
**Summary:** Make the CLI help block of the examples README equal to the `HELP` text
of the pinned burn-stack.

**Current behavior:**
The examples README has a "CLI Help Message" block. It is a copy of `HELP`, the
`--help` text of the shared flags in `burn_stack::examples::cli`. In that copy:

- the flag line says `--valid-batches <N>     The batches that a periodic validation reads`,
- the `BEHAVIOR OVERVIEW` list does not say that a full validation reads the whole
  split.

**Desired behavior:**
The burn-stack pin is at a pushed commit that has ticket 03. The "CLI Help Message"
block of the README is equal to the `HELP` text at that pin.

**Key interfaces:**

- The burn-stack pin: the two `rev` values in `Cargo.toml`, one in
  `[dependencies]` and one in `[dev-dependencies]`. The "Changes in both repos"
  section of `docs/agents/issue-tracker.md` gives the steps of a pin move.
- The `--help` output of an example prints `HELP` with no change, for example
  `cargo run --example reset-majority -- --help`.

**Acceptance criteria:**

- [ ] Both `rev` values name the same pushed burn-stack commit, and that commit has
      ticket 03. The `[patch]` is commented out. `cargo check` passes, and
      `Cargo.lock` agrees with the pin.
- [ ] If the new pin is a new minor version of burn-stack, the minor version of this
      crate increases (see the "Commits" rule of `CLAUDE.md`).
- [ ] The "CLI Help Message" block is equal to the `--help` output, line for line.
      If other lines of the block also differ, they change too.
- [ ] The block has the flag line
      `--valid-batches <N>     The batches that a validation reads (not a full validation)`.
- [ ] The `BEHAVIOR OVERVIEW` list of the block has the sentence "Some examples
      also run a full validation at each epoch end, which reads the whole split."
- [ ] `./scripts/check.sh` passes.

**Out of scope:**

- A change to `HELP`. burn-stack owns that text.
- A change to the validations of the examples. With `--valid-batches N`, the final
  validation of reset and tally stays capped. The "The decision on `valid_batches`"
  section of burn-stack ticket 03 gives the reason.
