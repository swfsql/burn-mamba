session after it. The term **Cache traversal** is in `../burn-stack/GLOSSARY.md`

**What to build:** The `CacheTensors` impls of each family live in a module with the
name of the glossary term: `family::cache_traversal`. The docs of burn-mamba call these
impls the cache traversal, and they say that it is the one list of the *tensors* of a
cache. In the adapters, some methods of `Block` and `BlockConfig` have the name of an
inherent method of their family. Each one calls that method by its type path. The
behaviour of the crate does not change.

**Current behaviour:**

- The module `family::capture` holds the cache traversal of each family. Its name gives
  only one of the operations that follow from the traversal. In the burn-stack glossary,
  **Captured step** is another term.
- Three docs of burn-mamba say "the one list of the fields" of a cache. The File Map
  line of the module says "the one field list". The glossary puts "field list" under
  _Avoid_, and the traversal visits tensors, not fields.
- Nine adapter methods call `self.x(..)`, and `x` is also the name of the trait method:
  `zero_cache`, `untied_params` and `muon_projections`, in each of the three families.
  Rust selects the inherent method, so the code is correct. But each call reads like an
  endless recursion.

**Desired behaviour:**

- The module is `family::cache_traversal`. The File Map line, the module docs and each
  doc link give this name.
- The docs say "cache traversal" and "the one list of the tensors". No doc of
  burn-mamba outside `.scratch/` says "field list".
- The nine delegations use the type path, for example
  `Mamba1::zero_cache(self, batch, device)`.
- The crate goes to 0.79.0, because the old public module path breaks (the decision of
  the user). The commit message states the break.

**Names:**

- `family::cache_traversal`: the new name of `family::capture`.
- The captured-step tests (`family::tests::capture`) keep their name. They test a
  captured step, which is the meaning of the word in the glossary.
- `CacheTensors`, `zip_tensors` and `TensorZip` keep their names. They are burn-stack
  identifiers, and "zip" is not under _Avoid_.
