# 05: Delete the backend traits with no bound site

Status: resolved

Blocked by: None

From the architecture review of 2026-11-03. Line numbers are those of commit
`42ca3d0e`.

**Files:** `src/mamba3/mod.rs:94-114`, `src/mamba2/ssd/serial_recalculated/serial_recalculated.rs:396`,
`src/mamba3/double_ssd/ssd/serial_recalculated/serial_recalculated.rs:155`,
`src/mamba3/single_ssd/ssd/serial_recalculated/serial_recalculated.rs:200`,
`src/mamba3/quat_scan/quat_scan.rs:224`.

**Problem:** 9 traits sit at this seam, but only 2 adapters are real: the default
body and `Autodiff`. Every plain impl is empty. Five public traits have no bound site
in `src`, `examples`, `benches` or burn-stack: 4 `…AutodiffBackendExt`, and
`Mamba3BackendExt`.

**Direction:** Delete the five traits. If nothing else calls
`decl_autodiff_backend_ext!`, delete it from burn-stack too. Before that, ask the
user whether a project outside these two repos names it.

**Also worth trying:** `#[extension_type]` for the optional inputs. Today they pass
as a placeholder plus a `bool` (`Restarts::op_inputs`, `seed_bnhpr` with `seeded`).

No memory or speed cost. The burn-stack half of the backend list is in
`../burn-stack/.scratch/arch-review-backlog/issues/01-backend-list.md`.

### Agent brief

**Category:** enhancement

**Summary:** Delete the five marker traits that no code bounds on (Part 1). Then try
`#[extension_type]` for the optional inputs of the three SSD ops (Part 2). Keep Part 2
only if the conditions below hold.

**Current behaviour:**

- Four extension traits send each custom backward to `Autodiff<B>`:
  `Mamba2BackendExt`, `Mamba3DoubleSsdBackendExt`, `Mamba3SingleSsdBackendExt` and
  `Mamba3QuatScanBackendExt`. A plain backend uses the default body.
- Five more public traits have no methods, and no code bounds on them:
  - `Mamba2AutodiffBackendExt`, `Mamba3DoubleSsdAutodiffBackendExt`,
    `Mamba3SingleSsdAutodiffBackendExt` and `Mamba3AutodiffBackendExt`. Each one comes
    from a call of burn-stack's `decl_autodiff_backend_ext!`.
  - `Mamba3BackendExt`. It has a call of `impl_backend_ext_for_burn_backends!`, and an
    empty blanket impl for `Autodiff<B, C>` in the module `mamba3::backwards`.
  - The preludes re-export all five.
- The three SSD ops (`ssd_serial_recalculated`, `double_ssd_serial_recalculated` and
  `single_ssd_serial_recalculated`) take each optional input as tensors plus a `bool`:
  - The restarts of a packed row: `keep_bn`, `origin_bhpr` and `resets`.
    `Restarts::op_inputs` makes them. All three ops take them.
  - The boundary seeds: `seed_bnhpr` and `seeded`. Only the single-SSD op takes them.
  - When the input is `None`, each tensor is a placeholder with each dimension 1. The
    op does not read it.

**Desired behaviour, Part 1 (the deletion, required):**

- The five traits are gone, with their macro calls, the blanket impl, the module
  `mamba3::backwards` and their re-exports.
- The four extension traits and their `Autodiff` impls do not change.
