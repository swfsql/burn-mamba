1//! # The run-time family choice
2//!
3//! [`burn_stack`] composes any [`Block`](burn_stack::modules::Block) into
4//! layers and networks, but `M` is fixed at the type level. This module lets a
5//! caller choose the family at *run time*, and serialize that choice. The choice
6//! sits at the block: [`MambaBlock`] is one enum over the three blocks, and it
7//! fills `Block` (`docs/adr/0009-family-choice-at-the-block.md`). So the
8//! containers need no enum of their own.
9//!
10//! [`MambaLatentNet`], [`MambaVocabNet`], [`MambaBidiLayers`] and
11//! [`MambaHNetVocabNet`] are type aliases, and each has a `{ shape, block }`
12//! config in [`config`]. The caches of a layer stack are a `Vec<MambaCache>`,
13//! and [`MambaScanOptions`] is the `Options` of the enum. A cache or scan
14//! options of the wrong family panic.
15//!
16//! This is also where the three families meet the generic stack: the
17//! `impl Block for Mamba{1,2,3}` and `impl BlockConfig for Mamba{1,2,3}Config`
18//! blocks are in [`adapters`]. The cache traversal of each family is in
19//! [`cache_traversal`].
20//!
21//! ## Muon: why the 3-D tensors are not "stacked matrices"
22//!
23//! The model keeps its fused projections, and only the Muon plan splits them.
24//! [`burn_stack::optim`] lets Muon own only the weights that a
25//! [`BlockConfig::muon_projections`](burn_stack::modules::BlockConfig::muon_projections)
26//! names. Each family lists there the weights that Muon can own, and splits
27//! each fused projection as its forward does. The item doc of each list gives
28//! what stays on the fallback optimizer, and why. The list of each family
29//! deliberately stops at rank 2. For the MIMO tensors of Mamba-3 this needs an
30//! argument, because their *shape* suggests the opposite conclusion.
31//!
32//! The *math* of MIMO does decompose along the rank. R write-channels add into
33//! one state, and the block reads that state in R ways. Each part is a
34//! **standalone** SISO run. This holds because the transition is a function of
35//! no sample. That is isotropy, not a property of MIMO, and no delta-rule shape
36//! has it (`info/mamba-3/mimo-as-batch.md` §5). So a `[nheads, mimo_rank,
37//! per_head_dim]` tensor looks like a stack of matrices that a stack-aware Muon
38//! could take one slice at a time.
39//!
40//! It is not. The paper deliberately does not instantiate the R maps, because
41//! that would multiply the parameter count of every per-head projection by R
42//! (`DP → DPR` *per head*). It keeps the SISO projection and scales its output
43//! element-wise to size R with a learnable vector (`DP + PR` per head). In the
44//! contraction notation of the appendix, `X = contract(PR, P → PR)(W_X, X')`:
45//! `P` is in both inputs *and* the output, so it is never contracted. So
46//! `mimo_x`/`mimo_z`/`mimo_o` are **diagonals**, and their matrix shape is a
47//! layout coincidence. To orthogonalise one would constrain a set of gains: R
48//! fixed measurement gains on one value, never R maps
49//! (`info/mamba-3/mimo-as-batch.md` §4).
50//!
51//! The part of MIMO that really is an R-fold matrix expansion is B/C
52//! (`DN → DNR`), which is in `in_proj` and already belongs to Muon. The other
53//! 3-D tensors are a bias (`b_bias_hmr`/`c_bias_hmr`), an initial condition
54//! (`init_state_hpr`), or a depthwise filter (the Mamba-1/2 conv): again
55//! diagonal or embedding-like.
56//!

85/// The scan options of a block, tagged with its family.
86///
87/// Each variant holds the scan options of its family, so a caller can choose
88/// the SSD path and the chunk length explicitly. The `*_default`
89/// constructors give the default scan options of the family, without making
90/// them the *only* choice.
91#[derive(Config, Debug)]
92pub enum MambaScanOptions {
93    /// Mamba-1 has no SSD chunking, so it has no scan options.
94    #[cfg(feature = "mamba1")]
95    Mamba1,
96    /// The scan options of Mamba-2.
97    #[cfg(feature = "mamba2")]
98    Mamba2(crate::mamba2::prelude::Mamba2ScanOptions),
99    /// The scan options of Mamba-3.
100    #[cfg(feature = "mamba3")]
101    Mamba3(crate::mamba3::prelude::Mamba3ScanOptions),
102}
103
104impl MambaScanOptions {
105    /// The default scan options of Mamba-2 (`SerialRecalculated`, optimal
106    /// chunk).
107    #[cfg(feature = "mamba2")]
108    pub fn mamba2_default() -> Self {
109        Self::Mamba2(Default::default())
110    }
111    /// The default scan options of Mamba-3 (`SerialRecalculated`, optimal
112    /// chunk).
113    #[cfg(feature = "mamba3")]
114    pub fn mamba3_default() -> Self {
115        Self::Mamba3(Default::default())
116    }
117}
