1//! # The run-time family choice
2//!
3//! [`burn_stack`] composes any [`Block`](burn_stack::modules::Block) into
4//! layers and networks, but `M` is fixed at the type level. This module lets a
5//! caller choose the family at *run time*, and serialize that choice. The choice
6//! sits at the block: [`MambaBlock`] is one enum over the three blocks, and it
7//! fills `Block` (`docs/adr/0009-family-choice-at-the-block.md`). So the
8//! containers need no enum of their own. [`MambaLatentNet`], [`MambaVocabNet`],
9//! [`MambaBidiLayers`] and [`MambaHNetVocabNet`] are type aliases, and each has
10//! a `{ shape, block }` config in [`config`]. [`MambaCaches`] is a flat list of
11//! slots, and [`MambaSsdPath`] is the `Options` of the enum. A cache or an SSD
12//! path of the wrong family panics.
13//!
14//! This is also where the three families meet the generic stack: the
15//! `impl Block for Mamba{1,2,3}`, `impl BlockConfig for Mamba{1,2,3}Config` and
16//! `impl CacheStack for Mamba{1,2,3}Caches` blocks are in [`adapters`].
17//!
18//! ## Muon: why the 3-D tensors are not "stacked matrices"
19//!
20//! The model keeps its fused projections, and only the Muon plan splits them.
21//! [`burn_stack::optim`] lets Muon own only the weights that a
22//! [`BlockConfig::muon_projections`](burn_stack::modules::BlockConfig::muon_projections)
23//! names. Each family lists there the weights that Muon can own, and splits
24//! each fused projection as its forward does. The item doc of each list gives
25//! what stays on the fallback optimizer, and why. The list of each family
26//! deliberately stops at rank 2. For the MIMO tensors of Mamba-3 this needs an
27//! argument, because their *shape* suggests the opposite conclusion.
28//!
29//! The *math* of MIMO does decompose along the rank: R write-channels summed
30//! into one state and read out R ways, each part a **standalone** SISO run.
31//! This holds because the transition is a function of no sample
32//! (`info/mamba-3/mimo-as-batch.md` §5: it is isotropy, not a property of
33//! MIMO, and no delta-rule shape has it). So a `[nheads, mimo_rank,
34//! per_head_dim]` tensor looks like a stack of matrices that a stack-aware Muon
35//! could take one slice at a time.
36//!
37//! It is not. The paper deliberately does not instantiate the R maps, because
38//! that would multiply the parameter count of every per-head projection by R
39//! (`DP → DPR` *per head*). It keeps the SISO projection and scales its output
40//! element-wise to size R with a learnable vector (`DP + PR` per head). In the
41//! contraction notation of the appendix, `X = contract(PR, P → PR)(W_X, X')`:
42//! `P` is in both inputs *and* the output, so it is never contracted. So
43//! `mimo_x`/`mimo_z`/`mimo_o` are **diagonals**, and their matrix shape is a
44//! layout coincidence. To orthogonalise one would constrain a set of gains: R
45//! fixed measurement gains on one value, never R maps
46//! (`info/mamba-3/mimo-as-batch.md` §4).
47//!
48//! The part of MIMO that really is an R-fold matrix expansion is B/C
49//! (`DN → DNR`), which is in `in_proj` and already belongs to Muon. The other
50//! 3-D tensors are a bias (`b_bias_hmr`/`c_bias_hmr`), an initial condition
51//! (`init_state_hpr`), or a depthwise filter (the Mamba-1/2 conv): again
52//! diagonal or embedding-like.
53//!

81/// An explicit, family-tagged SSD-path selector.
82///
83/// Each variant carries the concrete per-family path, so callers can choose
84/// the SSD path and the chunk length explicitly. The `*_default`
85/// constructors give the default path of the family, without making it the
86/// *only* option.
87#[derive(Debug, Clone)]
88pub enum MambaSsdPath {
89    /// Mamba-1 has no SSD chunking (path is the unit type).
90    #[cfg(feature = "mamba1")]
91    Mamba1,
92    /// Mamba-2 SSD path.
93    #[cfg(feature = "mamba2")]
94    Mamba2(crate::mamba2::prelude::Mamba2SsdPath),
95    /// Mamba-3 SSD path.
96    #[cfg(feature = "mamba3")]
97    Mamba3(crate::mamba3::prelude::Mamba3SsdPath),
98}
99
100impl MambaSsdPath {
101    /// The Mamba-2 default path (`SerialRecalculated`, optimal chunk).
102    #[cfg(feature = "mamba2")]
103    pub fn mamba2_default() -> Self {
104        Self::Mamba2(Default::default())
105    }
106    /// The Mamba-3 default path (`SerialRecalculated`, optimal chunk).
107    #[cfg(feature = "mamba3")]
108    pub fn mamba3_default() -> Self {
109        Self::Mamba3(Default::default())
110    }
