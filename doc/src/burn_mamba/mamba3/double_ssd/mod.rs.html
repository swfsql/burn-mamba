1//! # Double-SSD pathway (VikramLex-style)
2//!
3//! The Mamba-3 trapezoidal recurrence as **one standard SSD call per term**,
4//! with Mamba-2-like kernels:
5//!
6//! - γ-SSM: `hᵞₜ = αₜ hᵞₜ₋₁ + γₜ Bₜ xₜ`   (the current sample)
7//! - β-SSM: `hᵝₜ = αₜ hᵝₜ₋₁ + βₜ Bₜ₋ₗ xₜ₋ₗ`, one per `β` tap, at the own lag
8//!   `l` = [`Trapezoid::tap_lag`](crate::mamba3::trapezoid::Trapezoid::tap_lag)
9//!   of that tap, transported across its own gap
10//! - `hₜ = hᵞₜ + Σ hᵝₜ`.
11//!
12//! So there are **two** calls at the default, one under
13//! [`Trapezoid::None`](crate::mamba3::trapezoid::Trapezoid::None) (no tap to
14//! shift), and three under a two-tap pattern (its lags are different, so they
15//! cannot share a pass). It is simple and easy to verify. The cost is ~2× the
16//! intra-chunk and chunk-state memory of the
17//! [`single_ssd`](crate::mamba3::single_ssd) pathway, which stays at one call
18//! for any number of taps and suits a two-tap pattern better.
19//!
20//! `step` always uses this recurrence, for both cache variants.
21
