1//! # Quaternion (k=4) rotational state — the non-abelian generalisation of RoPE
2//!
3//! Mamba-3's data-dependent RoPE realises a **complex-valued** SSM: the state
4//! transition factors as a per-head scalar decay times a block-diagonal of
5//! `2×2` rotations (paper Prop. *Complex-to-Real SSM Equivalence*), and because
6//! `SO(2) ≅ U(1)` is **abelian** the cumulative rotation collapses to a
7//! `cumsum` of angles and is absorbed into `B`/`C` (the "RoPE trick", Prop.
8//! *Complex SSM, Data-Dependent RoPE Equivalence*).  See
9//! [`crate::mamba3::rotation::rope::apply_rope`].
10//!
11//! This module implements the next rung of the ladder: a **quaternion**
12//! (`k = 4`) rotational state, i.e. the transition's rotation lives in the
13//! left-isoclinic subgroup `SU(2) ⊂ SO(4)` instead of `SO(2)`.  Unit
14//! quaternions under multiplication are `SU(2)`, which is **non-abelian** and
15//! contains non-solvable finite subgroups (the binary icosahedral group
16//! `2I = SL(2,5)`, a double cover of `A₅`).  By Barrington's theorem this lifts
17//! the layer's reachable state-tracking from the solvable/`TC⁰` regime (parity,
18//! mod-k) toward `NC¹`, which abelian rotations provably cannot reach.
19//!
20//! ## What survives, what changes
21//!
22//! The key fact (derivable purely from telescoping + orthogonality, **without**
23//! commutativity — see the crate discussion) is that the RoPE *factoring*
24//! survives intact: with the **ordered** cumulative rotation
25//! `Pₜ = Rₜ Rₜ₋₁ ⋯ R₁`,
26//!
27//! ```text
28//!   Cₜᵀ (Rₜ⋯Rᵢ₊₁) Bᵢ  =  (Pₜᵀ Cₜ)ᵀ (Pᵢᵀ Bᵢ)  =  C̄ₜᵀ B̄ᵢ ,
29//! ```
30//!
31//! so the scalar-decay SSD core (`L ⊙ C̄B̄ᵀ`) is **unchanged** — only the
32//! projections `B̄ᵢ = Pᵢᵀ Bᵢ`, `C̄ₜ = Pₜᵀ Cₜ` are rotated.  What is lost is the
33//! closed-form `cumsum`: the cumulative rotation must be built by an
34//! **associative scan over the per-step quaternions** ([`quat_cumprod`]) rather
35//! than a sum of angles.  Because a product of unit quaternions is again a unit
36//! quaternion, the scan stays exactly orthogonal (no drift, no `wrap_angle`
37//! needed), and the cross-chunk carry is a single quaternion per block/head —
38//! the exact analogue of `cum_angle` in the existing caches.
39//!
40//! `SO(2)` (today's `apply_rope`) is the abelian collapse: restricting each
41//! quaternion to a single fixed axis makes them commute and reduces
42//! [`quat_cumprod`] to a `cumsum` of half-angles (asserted in the tests).
43//!
44//! ## Pipeline (the `k = 4` instantiation of the rotation block)
45//!
46//! ```text
47//!   per-step unit quaternion qₜ      (materialise from the in-projection; caller)
48//!        │  quat_cumprod (assoc. scan, + cross-chunk carry)
49//!        ▼
50//!   cumulative rotation Qₜ
51//!        │  rotate_state_rank_blocks(B, conj(Qₜ)) , rotate_state_rank_blocks(C, conj(Qₜ))
52//!        ▼
53//!   B̄, C̄  ──►  standard scalar-decay SSD  (unchanged)
54//! ```
55//!
56//! For [`RotationKind::Rotor4D`] the same pipeline runs with the two factors
57//! stacked along the block axis, and the last step becomes the two-sided
58//! `rotate_state_rank_blocks_two_sided(B, conj(Qₜ), Tₜ)`.
59//!
60//! ## `SO(4)`: the whole rotation group of a block ([`RotationKind::Rotor4D`])
61//!
62//! `SU(2)` is only half of what a 4-block can turn by. The general element of
63//! `SO(4) ≅ (SU(2)×SU(2))/±1` is the **two-sided** product
64//!
65//! ```text
66//!   Rₜ(v) = qₜ ⊗ v ⊗ p̄ₜ            (a rotor; left factor q, right factor p)
67//! ```
68//!
69//! and everything above survives it, because the factoring never used more
70//! than "the per-step maps compose, and each is orthogonal". Composing,
71//!
72//! ```text
73//!   Pₜ(v) = Qₜ ⊗ v ⊗ T̄ₜ ,   Qₜ = qₜ⊗⋯⊗q₁ ,  Tₜ = pₜ⊗⋯⊗p₁
74//!   Pₜ⁻¹(v) = Qₜ* ⊗ v ⊗ Tₜ    ⇒   B̄ᵢ = Qᵢ* ⊗ Bᵢ ⊗ Tᵢ ,  C̄ₜ likewise
75//! ```
76//!
77//! — note the conjugation reverses the right-hand order **twice**, so `T`
78//! accumulates by the *same* left fold as `Q`: one [`quat_cumprod`] over a
79//! doubled block axis, not a second, reversed scan. The cost over
80//! [`Quaternion4D`](RotationKind::Quaternion4D) is twice the generator
81//! channels, twice the scan's block axis, and one extra [`quat_mul`] per
82//! `B`/`C` application; the SSD core is still untouched.
83//!
84//! Why bother, when left and right factors *commute* with each other and so add
85//! no "more non-abelianness": left multiplication is **isoclinic** — `L_q` turns
86//! both invariant planes of the block by the same angle — so `SU(2)` cannot
87//! produce two independent plane angles, and in particular does not contain the
88//! abelian `SO(2)²` rotation it was introduced to generalise. The right factor
89//! is exactly what opens the maximal torus (plane angles `a−b`, `a+b` for the
90//! half-angles of `q`, `p`), making the ladder
91//! `Complex2D ⊂ Rotor4D ⊃ Quaternion4D` a real one. It also contains the
92//! adjoint action `v ↦ q ⊗ v ⊗ q̄`, i.e. a faithful `SO(3)` on the block's
93//! imaginary part — so a group like `A₅` can be tracked as itself rather than
94//! through its double cover `2I`, where `±g` denote one element but two
95//! different states. And as a representation of `SU(2)×SU(2)`, `ℍ` is the
96//! irreducible tensor product `(½,½)`, not `(½,0) ⊕ (0,½)`: no arrangement of
97//! left-only blocks reproduces it.
98//!
99//! `SO(4)` is the ceiling for `k = 4` (the largest norm-preserving transition
100//! group of a block), and `k = 4` is the last rung with a cheap closed form —
101//! at `k = 8` the octonions are non-associative and the scan itself breaks.
102//!
103//! ## The bottom rung: [`RotationKind::Real1D`]
104//!
105//! `k = 1`, the trivial group: no rotation, a purely real transition. It is the
106//! ablation the ladder is measured against, and it is *structural* rather than a
107//! zeroed knob — the in-projection spends no channels on rotation, the cache
108//! carries no accumulator ([`RotationState::Real`]), and `B`/`C` reach the SSD
109//! core untouched. Switching the rotation off is therefore a choice of *kind*;
110//! `rope_fraction` only ever narrows a rotation that exists. It is also the one
111//! kind with no pair to make, hence the only one that admits an **odd**
112//! `state_rank` — down to the scalar state `state_rank = 1`.
113//!
114//! Quaternion layout: the last axis has size 4 and holds `(w, x, y, z)` with
115//! `w` the real part.  A `state_rank` of `r = 4·J` is treated as `J` independent
116//! quaternion blocks; the rotation acts within each block, exactly as RoPE acts
117//! within each `2`-pair.  [`Mamba3`](crate::mamba3::mamba3::Mamba3) selects it
118//! with [`RotationKind::Quaternion4D`] and drives it through one
119//! [`RotationSpec`] (the SSD kernels themselves need no edits).

133/// Which rotational-state algebra the block uses for the data-dependent
134/// transition rotation absorbed into `B`/`C`.
135///
136/// - [`Real1D`](RotationKind::Real1D) — the trivial group: no rotation at all.
137///   The transition is the plain scalar decay, i.e. a **real** SSM (Mamba-2's
138///   transition under Mamba-3's trapezoid). The in-projection spends *no*
139///   channels on rotation and the cache carries no accumulator
140///   ([`RotationState::Real`]) — this is the rotation ablation, which is why
141///   `rope_fraction` has no `0.0` setting.
142/// - [`Complex2D`](RotationKind::Complex2D) — the abelian `SO(2)`/complex RoPE
143///   that Mamba-3 ships: cumulative *angles* via `cumsum`, applied by
144///   [`apply_rope`](crate::mamba3::rotation::rope::apply_rope). The default; behaviourally unchanged.
145/// - [`Quaternion4D`](RotationKind::Quaternion4D) — the non-abelian
146///   `SU(2) ⊂ SO(4)` quaternion rotation of this module: cumulative *product*
147///   via [`quat_cumprod`], applied by [`rotate_state_rank_blocks`]. Richer
148///   state-tracking; selects the [`RotationState::Quaternion`] cache accumulator.
149/// - [`Rotor4D`](RotationKind::Rotor4D) — the **whole** rotation group of a
150///   4-block, `SO(4) ≅ (SU(2)×SU(2))/±1`: a *two-sided* quaternion product
151///   `v ↦ q ⊗ v ⊗ p̄`. Two per-step quaternions instead of one (twice the
152///   generator channels, one scan over a doubled block axis); selects the
153///   [`RotationState::Rotor`] accumulator.
154///
155/// The kinds are a ladder — `Real1D ⊂ Complex2D ⊂ Rotor4D` and
156/// `Real1D ⊂ Quaternion4D ⊂ Rotor4D` — but the middle two are
157/// **incomparable**, which is why `Rotor4D` exists.
158/// Left multiplication is *isoclinic*: `L_q` turns both invariant planes of the
159/// block by the same angle (`L_i` sends `1↦i` **and** `j↦k`), so
160/// `Quaternion4D` cannot express two independent per-pair angles — it does not
161/// contain the abelian rotation it generalises. The right factor opens the full
162/// maximal torus (plane angles `a−b` and `a+b` for half-angles `a`, `b`), and
163/// with it every element of `SO(4)`.
164#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, serde::Serialize, serde::Deserialize)]
165pub enum RotationKind {
166    /// No rotation: a real transition (the trivial group). No rotation
167    /// channels, no cumulative accumulator, `B`/`C` pass through untouched.
168    Real1D,
169    /// Abelian complex (`SO(2)`) RoPE — the current default behaviour.
170    #[default]
171    Complex2D,
172    /// Non-abelian quaternion (`SU(2)`, left-isoclinic) rotation.
173    Quaternion4D,
174    /// The full `SO(4)` rotation of each 4-block: two-sided `v ↦ q ⊗ v ⊗ p̄`.
175    Rotor4D,
176}
177
178impl RotationKind {
179    /// How many cumulative-rotation quaternions the accumulator carries per
180    /// (head, 4-block): one for [`Quaternion4D`](RotationKind::Quaternion4D),
181    /// **two** for [`Rotor4D`](RotationKind::Rotor4D) (the left and right
182    /// factors). Meaningless for the non-quaternion kinds
183    /// ([`Complex2D`](RotationKind::Complex2D) accumulates angles,
184    /// [`Real1D`](RotationKind::Real1D) accumulates nothing) — reported as 1.
185    ///
186    /// The factors are stacked along one block axis, so every quaternion
187    /// primitive — the generator split, [`quat_from_scaled_axis`], the
188    /// [`quat_cumprod`] scan, [`quat_normalize`] — runs **once** over
189    /// `quat_factors · blocks` blocks and needs no `Rotor4D` branch of its own.
190    /// Only the *application* to `B`/`C` differs.
191    pub fn quat_factors(self) -> usize {
192        match self {
193            RotationKind::Rotor4D => 2,
194            RotationKind::Real1D | RotationKind::Complex2D | RotationKind::Quaternion4D => 1,
195        }
196    }
197}

199/// Everything the rotation needs from the block: which algebra, how much of
200/// `state_rank` it turns, and how far one step may turn it.
201///
202/// Carried by [`Mamba3`](crate::mamba3::mamba3::Mamba3) and handed to
203/// [`rotate_bc_forward`] / [`rotate_bc_step`] so that every site derives the
204/// per-step rotation from **one** definition — the two used to spell the
205/// formula out separately, which is exactly the kind of duplication that lets
206/// `forward` and `step` drift apart.
207#[derive(Debug, Clone, Copy, PartialEq)]
208pub struct RotationSpec {
209    /// Which rotational-state algebra ([`RotationKind`]).
210    pub kind: RotationKind,
211    /// How many leading `state_rank` entries are rotated (see
212    /// [`Mamba3Config::rope_fraction`](crate::mamba3::mamba3::Mamba3Config::rope_fraction)).
213    /// For [`RotationKind::Quaternion4D`] this is a multiple of 4; for
214    /// [`RotationKind::Real1D`] it is `0` and nothing reads it.
215    pub rope_dim: usize,
216    /// The per-step rotation bound in half-turns per unit `Δ`
217    /// ([`Mamba3Config::rotation_range`](crate::mamba3::mamba3::Mamba3Config::rotation_range)):
218    /// one step turns by at most `range · π · Δ`.
219    pub range: f64,
220}

225#[derive(Module, Debug, Default)]

228/// The cumulative-rotation accumulator carried between calls in a Mamba-3 cache
229/// — the variant matching the block's [`RotationKind`].
230///
231/// - [`Real`](RotationState::Real) — nothing at all: a real transition has no
232///   cumulative rotation to carry.
233/// - [`Angle`](RotationState::Angle) — abelian per-pair cumulative RoPE angle,
234///   shape `[batch, nheads, num_rope_angles]` (today's `cum_angle`).
235/// - [`Quaternion`](RotationState::Quaternion) — per-block cumulative unit
236///   quaternion, shape `[batch, nheads, blocks, 4]`, produced by
237///   [`quat_cumprod`].
238///
239/// This is the cache-level counterpart of [`RotationKind`]. It is defined here
240/// (the rotation module owns the accumulator type); substituting it for the
241/// pathway caches' `cum_angle_bha` field happens together with the forward/step
242/// wiring that consumes it.
243#[derive(Module, Debug)]
244pub enum RotationState {
245    /// [`RotationKind::Real1D`]'s empty accumulator: a real transition composes
246    /// nothing between calls. It carries a [`NoRotation`] only because Burn's
247    /// `Module` derive takes exactly one field per enum variant.
248    Real(NoRotation),
249    /// Abelian RoPE cumulative angle, shape `[batch, nheads, num_rope_angles]`.
250    Angle(Tensor<3>),
251    /// Quaternion cumulative rotation, shape `[batch, nheads, blocks, 4]`.
252    Quaternion(Tensor<4>),
253    /// `SO(4)` cumulative rotation, shape `[batch, nheads, 2·blocks, 4]`: the
254    /// left factors `Qₜ = qₜ⊗⋯⊗q₁` in the first `blocks` entries of the block
255    /// axis, the right factors `Tₜ = pₜ⊗⋯⊗p₁` in the second (see
256    /// [`split_rotor`]).
257    ///
258    /// One tensor rather than two so the scan, the normalisation and the cache
259    /// plumbing stay single-call; the conjugation in `v ↦ q v p̄` reverses the
260    /// right-hand order **twice**, so `T` accumulates with the very same
261    /// left-fold as `Q` and no reversed scan is needed.
262    Rotor(Tensor<4>),
263}
264
265impl RotationState {
266    /// The empty accumulator of [`RotationKind::Real1D`].
267    pub fn real() -> Self {
268        RotationState::Real(NoRotation)
269    }
270
271    /// Zero-initialised abelian angle accumulator `[batch, nheads, num_rope_angles]`.
272    pub fn zeros_angle(
273        batch: usize,
274        nheads: usize,
275        num_rope_angles: usize,
276        device: &Device,
277    ) -> Self {
278        RotationState::Angle(Tensor::zeros([batch, nheads, num_rope_angles], device))
279    }
280
281    /// Identity-initialised quaternion accumulator `[batch, nheads, blocks, 4]`
282    /// (every block is the identity quaternion `(1, 0, 0, 0)`).
283    pub fn identity_quaternion(
284        batch: usize,
285        nheads: usize,
286        blocks: usize,
287        device: &Device,
288    ) -> Self {
289        let w = Tensor::ones([batch, nheads, blocks, 1], device);
290        let xyz = Tensor::zeros([batch, nheads, blocks, 3], device);
291        RotationState::Quaternion(Tensor::cat(vec![w, xyz], 3))
292    }
293
294    /// The variant's name, for assertion messages.
295    fn variant(&self) -> &'static str {
296        match self {
297            RotationState::Real(_) => "Real",
298            RotationState::Angle(_) => "Angle",
299            RotationState::Quaternion(_) => "Quaternion",
300            RotationState::Rotor(_) => "Rotor",
301        }
302    }
303
304    /// Check this is the empty [`Real`](RotationState::Real) accumulator and
305    /// hand it back; panics on any other variant, so a cache built for a
306    /// rotating kind cannot be fed to a [`Real1D`](RotationKind::Real1D) block.
307    pub fn expect_real(self) -> Self {
308        match self {
309            RotationState::Real(_) => self,
310            other => panic!("RotationState is {}, expected Real", other.variant()),
311        }
312    }
313
314    /// Unwrap the abelian angle accumulator; panics if this is a quaternion.
315    pub fn angle(self) -> Tensor<3> {
316        match self {
317            RotationState::Angle(a) => a,
318            other => panic!("RotationState is {}, expected Angle", other.variant()),
319        }
320    }
321
322    /// Identity-initialised `SO(4)` accumulator `[batch, nheads, 2·blocks, 4]`
323    /// (both factors of every block are the identity quaternion `(1, 0, 0, 0)`).
324    pub fn identity_rotor(batch: usize, nheads: usize, blocks: usize, device: &Device) -> Self {
325        let w = Tensor::ones([batch, nheads, 2 * blocks, 1], device);
326        let xyz = Tensor::zeros([batch, nheads, 2 * blocks, 3], device);
327        RotationState::Rotor(Tensor::cat(vec![w, xyz], 3))
328    }
329
330    /// The identity accumulator for `kind` — the one place a fresh cache's
331    /// rotation state is built, for every pathway and both cache types.
332    pub fn identity(
333        kind: RotationKind,
334        batch: usize,
335        nheads: usize,
336        num_rope_angles: usize,
337        num_quat_blocks: usize,
338        device: &Device,
339    ) -> Self {
340        match kind {
341            RotationKind::Real1D => RotationState::real(),
342            RotationKind::Complex2D => {
343                RotationState::zeros_angle(batch, nheads, num_rope_angles, device)
344            }
345            RotationKind::Quaternion4D => {
346                RotationState::identity_quaternion(batch, nheads, num_quat_blocks, device)
347            }
348            RotationKind::Rotor4D => {
349                RotationState::identity_rotor(batch, nheads, num_quat_blocks, device)
350            }
351        }
352    }
353
354    /// Unwrap the quaternion accumulator; panics if this is an angle.
355    pub fn quaternion(self) -> Tensor<4> {
356        match self {
357            RotationState::Quaternion(q) => q,
358            other => panic!("RotationState is {}, expected Quaternion", other.variant()),
359        }
360    }
361
362    /// Unwrap the `SO(4)` accumulator (`[batch, nheads, 2·blocks, 4]`, both
363    /// factors stacked); panics for any other variant.
364    pub fn rotor(self) -> Tensor<4> {
365        match self {
366            RotationState::Rotor(q) => q,
367            other => panic!("RotationState is {}, expected Rotor", other.variant()),
368        }
369    }
370
371    /// The stacked quaternion accumulator for `kind`, together with the number
372    /// of **state** 4-blocks it covers — half its block axis for
373    /// [`RotationKind::Rotor4D`], which stacks two factors there.
374    ///
375    /// Panics on a variant the kind does not use: the two are the same rank and
376    /// differ only in the length of one axis, so a mismatched cache would
377    /// otherwise be reinterpreted rather than rejected.
378    fn quat_stack(self, kind: RotationKind) -> (Tensor<4>, usize) {
379        match (kind, self) {
380            (RotationKind::Quaternion4D, RotationState::Quaternion(q)) => {
381                let blocks = q.dims()[2];
382                (q, blocks)
383            }
384            (RotationKind::Rotor4D, RotationState::Rotor(q)) => {
385                let stacked = q.dims()[2];
386                assert_eq!(stacked % 2, 0, "a Rotor accumulator stacks two factors");
387                (q, stacked / 2)
388            }
389            (kind, other) => panic!(
390                "RotationState is {}, which is not {kind:?}'s accumulator",
391                other.variant()
392            ),
393        }
394    }
395
396    /// Run the [`NaN`/`Inf` guards](burn_stack::modules::misc::sanity) on the held tensor.
397    pub fn sanity(&self) {
398        match self {
399            RotationState::Real(_) => {}
400            RotationState::Angle(a) => burn_stack::modules::sanity(a),
401            RotationState::Quaternion(q) | RotationState::Rotor(q) => burn_stack::modules::sanity(q),
402        }
403    }
404}

410/// Hamilton product `a ⊗ b` of two quaternion tensors.
411///
412/// Both inputs have shape `[..., 4]` with the last axis ordered `(w, x, y, z)`;
413/// the product is computed component-wise and broadcasts over the leading dims.
414/// Quaternion multiplication is **non-commutative** (`a ⊗ b ≠ b ⊗ a` in
415/// general) but associative.
416///
417/// Identifying `ℝ⁴` with the quaternions, left-multiplication `v ↦ a ⊗ v` is
418/// exactly the action of the `4×4` rotation matrix [`quat_to_rot4`]`(a)`, so
419/// this is also how a rotation is *applied* to a state/`B`/`C` block (see
420/// [`rotate_state_rank_blocks`]).
421pub fn quat_mul<const D: usize>(a: Tensor<D>, b: Tensor<D>) -> Tensor<D> {
422    let n = D - 1;
423    let aw = a.clone().narrow(n, 0, 1);
424    let ax = a.clone().narrow(n, 1, 1);
425    let ay = a.clone().narrow(n, 2, 1);
426    let az = a.narrow(n, 3, 1);
427    let bw = b.clone().narrow(n, 0, 1);
428    let bx = b.clone().narrow(n, 1, 1);
429    let by = b.clone().narrow(n, 2, 1);
430    let bz = b.narrow(n, 3, 1);
431
432    // Hamilton product (each term is shape [..., 1]).
433    let w = aw.clone() * bw.clone()
434        - ax.clone() * bx.clone()
435        - ay.clone() * by.clone()
436        - az.clone() * bz.clone();
437    let x = aw.clone() * bx.clone() + ax.clone() * bw.clone() + ay.clone() * bz.clone()
438        - az.clone() * by.clone();
439    let y = aw.clone() * by.clone() - ax.clone() * bz.clone()
440        + ay.clone() * bw.clone()
441        + az.clone() * bx.clone();
442    let z = aw * bz + ax * by - ay * bx + az * bw;
443
444    Tensor::cat(vec![w, x, y, z], n)
445}

447/// Quaternion conjugate `q* = (w, −x, −y, −z)` (shape `[..., 4]`).
448///
449/// For a **unit** quaternion `q* = q⁻¹`, and the corresponding rotation matrix
450/// satisfies `Lₚ⋆ = Lₚᵀ = Lₚ⁻¹`.  Hence rotating by the *inverse* cumulative
451/// rotation (`B̄ = Pᵀ B`) is `rotate_state_rank_blocks(B, conj(Q))`.
452pub fn quat_conj<const D: usize>(q: Tensor<D>) -> Tensor<D> {
453    let n = D - 1;
454    let w = q.clone().narrow(n, 0, 1);
455    let xyz = q.narrow(n, 1, 3);
456    Tensor::cat(vec![w, -xyz], n)
457}

459/// Normalise quaternions to unit norm along the last axis (shape `[..., 4]`).
460///
461/// The per-step rotation is materialised from a raw, unconstrained projection
462/// and normalised here so it is a genuine unit quaternion (an element of
463/// `SU(2)`), the analogue of `tanh(θ)·π` bounding the RoPE angle.  A tiny floor
464/// guards the zero-quaternion.
465pub fn quat_normalize<const D: usize>(q: Tensor<D>) -> Tensor<D> {
466    let n = D - 1;
467    // Clamp the sum-of-squares *before* `sqrt`: at a zero quaternion the forward
468    // `sqrt(0)=0` is fine, but `sqrt`'s backward is `1/(2·0)=∞`, and `∞·(2·0)=NaN`.
469    // Clamping pre-`sqrt` puts the degenerate point in `clamp_min`'s flat region,
470    // so its gradient is a finite 0 (and a genuine unit quaternion, sumsq=1, is
471    // untouched). The floor also keeps `norm` away from 0 for the division.
472    //
473    // The floor is the dtype-aware `div_eps` applied to the *sum-of-squares*
474    // (giving a norm floor of `√div_eps`). It must engage as a representable
475    // normal in the working dtype: in f16 a `div_eps²`-sized floor (~5e-7) would
476    // underflow below the min-normal (~6.1e-5) and silently no-op, so we floor
477    // the squared quantity at `div_eps` itself, which sits above each format's
478    // denormal floor by construction.
479    let eps = burn_stack::utils::div_eps(q.dtype());
480    let norm = (q.clone() * q.clone()).sum_dim(n).clamp_min(eps).sqrt();
481    q / norm
482}
483
484/// Euclidean norm over the last axis, formed **scale-free** so it cannot
485/// overflow: the components are divided by their (detached) largest magnitude
486/// before squaring, and the result is scaled back.
487///
488/// Squaring the raw components is the obvious way and the wrong one here,
489/// because the inputs are raw in-projection channels: `‖r‖²` overflows f32 at
490/// `|r| ≈ 2e19` and **f16 at `|r| ≈ 250`**, which is an ordinary activation.
491/// The overflow does not announce itself — `∞` divides back to `0`, so a very
492/// large generator would silently produce *no* rotation, the exact opposite of
493/// the intended "turn as far as the bound allows". Same trick, same reason, as
494/// [`RmsNorm`](burn_stack::modules::RmsNorm)'s fp16 path.
495///
496/// The sum of squares is floored by `div_eps` before the `sqrt`, so a zero
497/// vector lands in `clamp_min`'s flat region and backprops to a finite `0`
498/// instead of `sqrt`'s singular `1/(2·0)`.
499///
500/// # Shapes
501/// - `t`  : `[..., n]`
502/// - out  : `[..., 1]`
503pub(crate) fn safe_norm<const D: usize>(t: Tensor<D>) -> Tensor<D> {
504    let n = D - 1;
505    let eps = burn_stack::utils::div_eps(t.dtype());
506    // Detached: the rescaling is a numerical device, not part of the function
507    // being differentiated (`d‖t‖/dt = t̂` either way).
508    let scale = t.clone().abs().max_dim(n).detach() + eps; // [..., 1]
509    let unit = t / scale.clone(); // components ≤ 1
510    (unit.clone() * unit).sum_dim(n).clamp_min(eps).sqrt() * scale
511}

513/// Materialise a unit quaternion from a **scaled rotation vector** `g ∈ ℝ³`
514/// (axis · angle) via the exponential map — the data-dependent "materialise
515/// `Rₜ`" step, analogous to RoPE's `Δₜ · π · tanh(θₜ)` angle.
516///
517/// With `‖g‖ = angle` and `ĝ = g / angle` the axis, returns the unit quaternion
518/// `q = (cos(angle/2), sin(angle/2)·ĝ)`.  A vanishing `g` maps to the identity
519/// `(1, 0, 0, 0)`, so scaling `g` by a small `Δₜ` (the discretisation step)
520/// yields a near-identity rotation — exactly the regime where a small step
521/// barely rotates the state.  The `sin(angle/2)/angle` factor is the numerically
522/// stable form of the (otherwise `0/0`) per-component scale near `g = 0`.
523///
524/// # Shapes
525/// - `g` : `[..., 3]`
526/// - out : `[..., 4]` (ordered `(w, x, y, z)`), unit norm.
527pub fn quat_from_scaled_axis<const D: usize>(g: Tensor<D>) -> Tensor<D> {
528    let n = D - 1;
529    // `safe_norm` both guards the origin (a zero generator would otherwise hit
530    // `sqrt`'s singular backward and yield NaN — the FiLM-triggered decoder
531    // NaN) and keeps the sum of squares from overflowing at large `g`.
532    let angle = safe_norm(g.clone()); // [..., 1]
533    let half = angle.clone() * 0.5;
534    let w = half.clone().cos(); // [..., 1]
535    // sin(angle/2) / angle  → 1/2 as angle → 0 (no rotation); `angle ≥ √div_eps`
536    // after the pre-`sqrt` clamp above, so the division is already guarded.
537    let scale = half.sin() / angle; // [..., 1]
538    let v = g * scale; // [..., 3]
539    quat_normalize(Tensor::cat(vec![w, v], n))
540}

542/// Bound a rotation vector's **magnitude**, leaving its direction alone:
543/// returns `max_angle · tanh(‖r‖) · r̂`.
544///
545/// This is the quaternion counterpart of the abelian path's `π·tanh(ϑ)`, and
546/// the difference is deliberate. Squashing each of the three raw channels
547/// *separately* would bound the rotation vector to a **cube**: the reachable
548/// angle would depend on the axis (`max_angle` about a coordinate axis but
549/// `√3·max_angle` about the diagonal), and — worse — `tanh` applied per
550/// component moves the *direction* too, so the axis a given projection selects
551/// would depend on how large the projection is. Bounding the norm keeps the
552/// axis exactly `r̂` and the angle a function of `‖r‖` alone, so axis and angle
553/// are independent knobs.
554///
555/// Near `r = 0` the map is `≈ max_angle · r` (the `tanh(n)/n → 1` limit); the
556/// `sum-of-squares` floor is the same pre-`sqrt` clamp
557/// [`quat_from_scaled_axis`] uses, and puts the degenerate point in the flat
558/// region of `clamp_min` with the correct finite gradient.
559///
560/// # Shapes
561/// - `r`  : `[..., 3]`
562/// - out  : `[..., 3]`, with `‖out‖ ≤ max_angle` (attained once `tanh` saturates).
563pub fn bound_rotation_vector<const D: usize>(r: Tensor<D>, max_angle: f64) -> Tensor<D> {
564    let norm = safe_norm(r.clone()); // [..., 1]
565    let scale = norm.clone().tanh() * max_angle / norm;
566    r * scale
567}

569/// Materialise the `4×4` orthogonal matrix of left-multiplication by `q`.
570///
571/// Maps `q` of shape `[..., 4]` to `[..., 4, 4]` such that, for `v` of shape
572/// `[..., 4]`, `Lq · v == quat_mul(q, v)`.  Concretely (rows = output coords,
573/// cols = input coords, all in `(w, x, y, z)` order):
574///
575/// ```text
576///   ⎡ w  -x  -y  -z ⎤
577///   ⎢ x   w  -z   y ⎥
578///   ⎢ y   z   w  -x ⎥
579///   ⎣ z  -y   x   w ⎦
580/// ```
581///
582/// For a unit `q` this is orthogonal with `det = 1` (a left-isoclinic rotation).
583/// Provided mainly for the generic / verification path; the cheap way to apply a
584/// rotation is [`rotate_state_rank_blocks`] (a quaternion product, no `4×4`
585/// materialisation).  `DR` must equal `D + 1`.
586pub fn quat_to_rot4<const D: usize, const DR: usize>(q: Tensor<D>) -> Tensor<DR> {
587    assert_eq!(D + 1, DR, "quat_to_rot4 maps rank D to rank D+1");
588    let n = D - 1;
589    let w = q.clone().narrow(n, 0, 1);
590    let x = q.clone().narrow(n, 1, 1);
591    let y = q.clone().narrow(n, 2, 1);
592    let z = q.narrow(n, 3, 1);
593
594    // Each row is a [..., 4] tensor (the four column entries).
595    let row0 = Tensor::cat(vec![w.clone(), -x.clone(), -y.clone(), -z.clone()], n);
596    let row1 = Tensor::cat(vec![x.clone(), w.clone(), -z.clone(), y.clone()], n);
597    let row2 = Tensor::cat(vec![y.clone(), z.clone(), w.clone(), -x.clone()], n);
598    let row3 = Tensor::cat(vec![z, -y, x, w], n);
599
600    // Stack the rows along a freshly inserted row axis → [..., 4, 4].
601    Tensor::cat(
602        vec![
603            row0.unsqueeze_dim::<DR>(n),
604            row1.unsqueeze_dim::<DR>(n),
605            row2.unsqueeze_dim::<DR>(n),
606            row3.unsqueeze_dim::<DR>(n),
607        ],
608        n,
609    )
610}

616/// Apply a per-block quaternion rotation to the `state_rank` axis of `v`.
617///
618/// `v` has shape `[..., state_rank]` with `state_rank = 4·J`, viewed as `J`
619/// independent quaternion blocks; `q` has shape `[..., J, 4]` (one unit
620/// quaternion per block, same leading dims as `v`).  Returns `q ⊗ v` per block,
621/// i.e. the rotation `L_q` applied within each `4`-block, reshaped back to
622/// `[..., state_rank]`.
623///
624/// This is the generalisation of RoPE's per-pair `2×2` rotation to per-block
625/// `4×4`.  To rotate by the *inverse* cumulative rotation when absorbing into
626/// `B`/`C` (`B̄ = Pᵀ B`), pass `q = conj(Qcum)`:
627/// `rotate_state_rank_blocks(b, conj(qcum))`.
628///
629/// `DB` must equal `D + 1` (the block-split inserts the `J` axis).
630pub fn rotate_state_rank_blocks<const D: usize, const DB: usize>(
631    v: Tensor<D>,
632    q: Tensor<DB>,
633) -> Tensor<D> {
634    assert_eq!(
635        D + 1,
636        DB,
637        "rotate_state_rank_blocks splits one axis into (J, 4)"
638    );
639    let dims = v.dims();
640    let state_rank = dims[D - 1];
641    assert_eq!(
642        state_rank % 4,
643        0,
644        "state_rank must be a multiple of 4 (quaternion blocks)"
645    );
646    let blocks = state_rank / 4;
647
648    // Build the block-split shape [..., J, 4] (rank DB) and the flat shape
649    // [..., state_rank] (rank D) for the round trip.
650    let mut split_shape = [0usize; DB];
651    split_shape[..D - 1].copy_from_slice(&dims[..D - 1]);
652    split_shape[DB - 2] = blocks;
653    split_shape[DB - 1] = 4;
654
655    let v_blocks = v.reshape(split_shape); // [..., J, 4]
656    let rotated = quat_mul(q, v_blocks); // L_q applied per block
657    rotated.reshape(dims) // [..., state_rank]
658}

660/// Apply a per-block **two-sided** quaternion rotation to the `state_rank` axis
661/// of `v`: `v ↦ ql ⊗ v ⊗ qr` per 4-block.
662///
663/// This is the general `SO(4)` element ([`RotationKind::Rotor4D`]); pass
664/// `qr = (1,0,0,0)` to recover [`rotate_state_rank_blocks`]. Absorbing the
665/// *inverse* cumulative rotation into `B`/`C` (`B̄ = P⁻¹B` with
666/// `P(v) = Q v T̄`) is `ql = conj(Q)`, `qr = T` — note the conjugate is on the
667/// **left** factor only.
668///
669/// Shapes as [`rotate_state_rank_blocks`]: `v` is `[..., state_rank]`, both
670/// quaternions `[..., J, 4]`, and `DB = D + 1`.
671pub fn rotate_state_rank_blocks_two_sided<const D: usize, const DB: usize>(
672    v: Tensor<D>,
673    ql: Tensor<DB>,
674    qr: Tensor<DB>,
675) -> Tensor<D> {
676    assert_eq!(
677        D + 1,
678        DB,
679        "rotate_state_rank_blocks_two_sided splits one axis into (J, 4)"
680    );
681    let dims = v.dims();
682    let state_rank = dims[D - 1];
683    assert_eq!(
684        state_rank % 4,
685        0,
686        "state_rank must be a multiple of 4 (quaternion blocks)"
687    );
688
689    let mut split_shape = [0usize; DB];
690    split_shape[..D - 1].copy_from_slice(&dims[..D - 1]);
691    split_shape[DB - 2] = state_rank / 4;
692    split_shape[DB - 1] = 4;
693
694    let v_blocks = v.reshape(split_shape); // [..., J, 4]
695    quat_mul(quat_mul(ql, v_blocks), qr).reshape(dims)
696}

698/// Split a stacked [`RotationState::Rotor`] accumulator `[..., 2·J, 4]` into
699/// its `(left, right)` factors, each `[..., J, 4]`.
700pub fn split_rotor<const D: usize>(q: Tensor<D>) -> (Tensor<D>, Tensor<D>) {
701    let stacked = q.dims()[D - 2];
702    assert_eq!(stacked % 2, 0, "a Rotor accumulator stacks two factors");
703    let blocks = stacked / 2;
704    (
705        q.clone().narrow(D - 2, 0, blocks),
706        q.narrow(D - 2, blocks, blocks),
707    )
708}

710// ---------------------------------------------------------------------------
711// Cumulative rotation scan (the associative, non-abelian replacement for cumsum)
712// ---------------------------------------------------------------------------
713
714/// Cumulative (ordered, left-accumulating) quaternion product along the
715/// sequence axis, with a cross-chunk carry.
716///
717/// This is the non-abelian analogue of the cumulative *sum of angles* used by
718/// RoPE: where complex rotations compose by adding angles (a `cumsum`),
719/// quaternions compose by multiplication, which is order-dependent, so a real
720/// scan is required.
721///
722/// # Shapes
723/// - `q_bshj4` : `[batch, sequence, nheads, J, 4]` per-step **unit** quaternions
724///   (block count `J = state_rank / 4`).
725/// - `init`    : optional carry `[batch, nheads, J, 4]` — the cumulative
726///   rotation at the end of the previous chunk (identity `(1,0,0,0)` for a fresh
727///   start).
728/// - returns `(cum, final_carry)` where `cum` is `[batch, sequence, nheads, J, 4]`
729///   with `cum[:, t] = qₜ ⊗ qₜ₋₁ ⊗ ⋯ ⊗ q₀ ⊗ init` (newest on the left, matching
730///   `Pₜ = Rₜ ⋯ R₁`), and `final_carry` `[batch, nheads, J, 4]` is `cum[:, −1]`
731///   to thread into the next chunk.
732///
733/// Running this over a split sequence while threading `final_carry` is exactly
734/// equal to running it over the whole sequence (asserted in the tests) — the
735/// chunked-prefill / streaming guarantee, here for the rotation accumulator.
736///
737/// Implemented as a **Hillis–Steele** inclusive associative scan: the quaternion
738/// product is associative (just not commutative), so a log-depth scan applies as
739/// long as operand order is preserved (newest-on-left). Each doubling step is a
740/// single full-tensor [`quat_mul`] plus a sequence shift, so the *sequential
741/// dependency depth* is `O(log sequence)` rather than the `O(sequence)` of a
742/// token-by-token loop — the same values, but a handful of large batched kernels
743/// instead of thousands of serialized tiny ones (and a correspondingly shallow
744/// autodiff graph). The sequential reference it replaces is kept as a test oracle
745/// (`quat_cumprod_sequential` in the tests module) and asserted equal on values
746/// **and** gradients.
747pub fn quat_cumprod(q_bshj4: Tensor<5>, init: Option<Tensor<4>>) -> (Tensor<5>, Tensor<4>) {
748    let [batch, sequence, nheads, blocks, _four] = q_bshj4.dims();
749    let device = q_bshj4.device();
750
751    // Pure prefix product Pₜ = qₜ ⊗ qₜ₋₁ ⊗ ⋯ ⊗ q₀ by Hillis–Steele doubling.
752    // Invariant after each step with offset `d`: a[t] holds the product of the
753    // window [t .. max(t-2d+1, 0)] (newest on the left). After ⌈log₂ sequence⌉
754    // doublings the window covers [t .. 0], i.e. a[t] = Pₜ.
755    let mut a = q_bshj4;
756    let mut offset = 1usize;
757    while offset < sequence {
758        // shifted[t] = a[t-offset] for t ≥ offset, else the identity quaternion
759        // (1,0,0,0) — so the first `offset` prefixes pass through unchanged
760        // (a ⊗ identity = a).
761        let ident = {
762            let w = Tensor::ones([batch, offset, nheads, blocks, 1], &device);
763            let xyz = Tensor::zeros([batch, offset, nheads, blocks, 3], &device);
764            Tensor::cat(vec![w, xyz], 4)
765        };
766        let shifted = Tensor::cat(vec![ident, a.clone()], 1).narrow(1, 0, sequence);
767        // Recent block (a) on the left, older block (shifted) on the right.
768        a = quat_mul(a, shifted);
769        offset *= 2;
770    }
771
772    // Fold the cross-chunk carry once: cumₜ = Pₜ ⊗ init. `init` (the previous
773    // chunk's final cumulative rotation) is the oldest factor, hence on the
774    // right; a missing carry is the identity and needs no multiply.
775    let cum = match init {
776        Some(init_bhj4) => {
777            assert_eq!([batch, nheads, blocks, 4], init_bhj4.dims());
778            quat_mul(a, init_bhj4.unsqueeze_dim::<5>(1)) // [batch, 1, nheads, J, 4] broadcasts over seq
779        }
780        None => a,
781    };
782
783    let final_carry = cum.clone().narrow(1, sequence - 1, 1).squeeze_dim::<4>(1); // [batch, nheads, J, 4]
784    (cum, final_carry)
785}

791/// Apply a per-block quaternion rotation to the first `rope_width` entries of
792/// the `state_rank` axis (a multiple of 4); the remainder passes through. The
793/// quaternion analogue of [`apply_rope_partial`].
794///
795/// `q` has one quaternion per rotated block (`rope_width / 4` of them). `DB`
796/// must equal `D + 1`.
797pub fn rotate_blocks_partial<const D: usize, const DB: usize>(
798    v: Tensor<D>,
799    q: Tensor<DB>,
800    rope_width: usize,
801) -> Tensor<D> {
802    let r = v.dims()[D - 1];
803    debug_assert!(
804        rope_width > 0,
805        "a quaternion kind always turns at least one block; a real transition is RotationKind::Real1D"
806    );
807    if rope_width == r {
808        rotate_state_rank_blocks::<D, DB>(v, q)
809    } else {
810        let head = v.clone().narrow(D - 1, 0, rope_width);
811        let tail = v.narrow(D - 1, rope_width, r - rope_width);
812        let head_rot = rotate_state_rank_blocks::<D, DB>(head, q);
813        Tensor::cat(vec![head_rot, tail], D - 1)
814    }
815}

817/// Two-sided counterpart of [`rotate_blocks_partial`]: rotates the first
818/// `rope_width` entries of the `state_rank` axis by `v ↦ ql ⊗ v ⊗ qr`, passing
819/// the remainder through.
820pub fn rotate_blocks_two_sided_partial<const D: usize, const DB: usize>(
821    v: Tensor<D>,
822    ql: Tensor<DB>,
823    qr: Tensor<DB>,
824    rope_width: usize,
825) -> Tensor<D> {

827    debug_assert!(rope_width > 0, "see rotate_blocks_partial");
828    if rope_width == r {
829        rotate_state_rank_blocks_two_sided::<D, DB>(v, ql, qr)
830    } else {

832        let tail = v.narrow(D - 1, rope_width, r - rope_width);
833        let head_rot = rotate_state_rank_blocks_two_sided::<D, DB>(head, ql, qr);
834        Tensor::cat(vec![head_rot, tail], D - 1)
835    }
836}

842/// The abelian per-step angle increment `θ̂ₜ = Δₜ · range·π·tanh(ϑₜ)`, one per
843/// head and rotation pair.
844///
845/// `DP1 = D + 1`: the head axis is inserted before the pair axis, so a
846/// sequence-shaped call (`rot [b, s, a]`, `dt [b, s, h]`) yields `[b, s, h, a]`
847/// and a single-token call (`rot [b, a]`, `dt [b, h]`) yields `[b, h, a]`.
848pub fn angle_increment<const D: usize, const DP1: usize>(
849    rot: Tensor<D>,
850    dt: Tensor<D>,
851    range: f64,
852) -> Tensor<DP1> {
853    assert_eq!(D + 1, DP1, "angle_increment inserts the head axis");
854    let bounded = rot.tanh() * (range * std::f64::consts::PI);
855    dt.unsqueeze_dim::<DP1>(D) * bounded.unsqueeze_dim::<DP1>(D - 1)
856}
857
858/// The quaternion per-step rotation vector `gₜ = Δₜ · range·π·tanh(‖r‖)·r̂`, one
859/// per head and quaternion block (feed it to [`quat_from_scaled_axis`]).
860///
861/// The magnitude — not each component — is bounded, so the axis is exactly the
862/// direction of the projection; see [`bound_rotation_vector`].
863///
864/// Unlike the abelian [`angle_increment`], the generators are projected **per
865/// head**: `rot` carries `nheads · 3 · J` channels, so every head turns about
866/// its own data-dependent axis rather than sharing one axis and differing only
867/// in `Δ`. Sharing would make the heads' rotations a one-parameter family of
868/// each other — the abelian path can afford that (its rotations commute, so a
869/// per-head angle is the only freedom there is), but for a non-abelian
870/// transition the axis *is* the expressive part: two heads turning about
871/// different axes track different words, which is the whole point of having
872/// more than one.
873///
874/// `DP1 = D + 1`, `DP2 = D + 2`: a sequence-shaped call (`rot [b, s, h·3·J]`,
875/// `dt [b, s, h]`) yields `[b, s, h, J, 3]` and a single-token call
876/// (`rot [b, h·3·J]`, `dt [b, h]`) yields `[b, h, J, 3]`.
877pub fn generator_increment<const D: usize, const DP1: usize, const DP2: usize>(
878    rot: Tensor<D>,
879    dt: Tensor<D>,
880    blocks: usize,
881    range: f64,
882) -> Tensor<DP2> {
883    assert_eq!(D + 1, DP1, "generator_increment splits (3·J) into (J, 3)");
884    assert_eq!(
885        D + 2,
886        DP2,
887        "generator_increment also splits off the head axis"
888    );
889    let dims = rot.dims();
890    let nheads = dt.dims()[D - 1];
891    assert_eq!(
892        dims[D - 1],
893        nheads * 3 * blocks,
894        "the rotation channels are three generators per (head, quaternion block)"
895    );
896    // [..., h·3·J] → [..., h, J, 3]
897    let mut split = [0usize; DP2];
898    split[..D - 1].copy_from_slice(&dims[..D - 1]);
899    split[DP2 - 3] = nheads;
900    split[DP2 - 2] = blocks;
901    split[DP2 - 1] = 3;
902    let bounded = bound_rotation_vector::<DP2>(rot.reshape(split), range * std::f64::consts::PI);
903    // Δ is per head: broadcast it over (J, 3)
904    bounded * dt.unsqueeze_dim::<DP1>(D).unsqueeze_dim::<DP2>(D + 1)
905}

911/// Rotate `B`/`C` for a **full sequence** by the data-dependent transition
912/// rotation, returning the rotated projections and the new cumulative
913/// [`RotationState`] to store in the cache.
914///
915/// Branches on [`RotationKind`]:
916/// - [`Real1D`](RotationKind::Real1D): nothing happens — `B`/`C` pass through
917///   and the (empty) accumulator is handed back. `rot` is `None` there, since
918///   the block projects no rotation channels at all.
919/// - [`Complex2D`](RotationKind::Complex2D): the abelian RoPE — cumulative
920///   angle `cumsum` continued from `prev`, then [`apply_rope_partial`]. Exactly
921///   the original Mamba-3 behaviour.
922/// - [`Quaternion4D`](RotationKind::Quaternion4D): per-step unit quaternion
923///   [`quat_from_scaled_axis`] (the in-projection generators scaled per-head by
924///   `Δ`), composed by [`quat_cumprod`] continuing the cached quaternion, then
925///   applied to `B`/`C` as `rotate(·, conj(Qₜ))` over the first `4·blocks`
926///   state-rank entries.
927///
928/// # Shapes
929/// - `rot_bsa` : `[batch, sequence, num_rotation_channels]` — the in-projection
930///   rotation channels (angles for Complex2D, `3·blocks` quaternion generators
931///   for Quaternion4D), `None` for Real1D, which projects none.
932/// - `dt_bsh`  : `[batch, sequence, nheads]` (`Δ`).
933/// - `b_bsmhr` / `c_bsmhr` : `[batch, sequence, mimo_rank, nheads, state_rank]`.
934pub fn rotate_bc_forward(
935    rot_bsa: Option<Tensor<3>>,
936    dt_bsh: Tensor<3>,
937    prev: RotationState,
938    b_bsmhr: Tensor<5>,
939    c_bsmhr: Tensor<5>,
940    spec: RotationSpec,
941) -> (Tensor<5>, Tensor<5>, RotationState) {
942    let [batch, sequence, mimo_rank, nheads, _state_rank] = b_bsmhr.dims();
943    let RotationSpec {
944        kind,
945        rope_dim,
946        range,
947    } = spec;
948    // Only `Real1D` projects no rotation channels, and it never reads them.
949    let rot = |r: Option<Tensor<3>>| r.expect("a rotating kind projects rotation channels");
950    match kind {
951        RotationKind::Real1D => (b_bsmhr, c_bsmhr, prev.expect_real()),
952        RotationKind::Complex2D => {
953            let rot_bsa = rot(rot_bsa);
954            let prev_angle_bha = prev.angle();
955            let num_rope_angles = prev_angle_bha.dims()[2];
956            let raw_angles_bsha = angle_increment::<3, 4>(rot_bsa, dt_bsh, range);
957            let cum_angles_bsha = prev_angle_bha.unsqueeze_dim::<4>(1) + raw_angles_bsha.cumsum(1);
958            let cum_angles_bsmha = cum_angles_bsha.clone().unsqueeze_dim::<5>(2).expand([
959                batch,
960                sequence,
961                mimo_rank,
962                nheads,
963                num_rope_angles,
964            ]);
965            let rotate_pairwise = mimo_rank == 1;
966            let b = apply_rope_partial::<5>(
967                b_bsmhr,
968                cum_angles_bsmha.clone(),
969                rope_dim,
970                rotate_pairwise,
971            );
972            let c = apply_rope_partial::<5>(c_bsmhr, cum_angles_bsmha, rope_dim, rotate_pairwise);
973            let last = wrap_angle(
974                cum_angles_bsha
975                    .narrow(1, sequence - 1, 1)
976                    .squeeze_dim::<3>(1),
977            );
978            (b, c, RotationState::Angle(last))
979        }
980        RotationKind::Quaternion4D | RotationKind::Rotor4D => {
981            // `stack` is the generator/scan block axis: `blocks` for
982            // Quaternion4D, `2·blocks` for Rotor4D (left factors, then right).
983            // Everything up to the *application* is factor-agnostic and runs
984            // once over the whole stack.
985            let (prev_q_bhk4, blocks) = prev.quat_stack(kind);
986            let stack = prev_q_bhk4.dims()[2];
987            // The rotated width is a whole number of quaternion blocks, and
988            // the cache was sized for exactly that many.
989            assert_eq!(rope_dim, blocks * 4, "cache/block rotation width mismatch");
990            let rope_width = rope_dim;
991            // Generators [b,s,h,stack,3]: the raw channels bounded to an angle
992            // of at most `range·π` (see `generator_increment`) and scaled
993            // per-head by Δ. The bound is load-bearing, not cosmetic: an
994            // unbounded `g = rot·Δ` overflows f32 to `inf` for a large
995            // in-projection activation, and `quat_from_scaled_axis`'s `cos(∞)`
996            // then yields a forward NaN.
997            let g_bshk3 = generator_increment::<3, 4, 5>(rot(rot_bsa), dt_bsh, stack, range);
998            let q_step_bshk4 = quat_from_scaled_axis::<5>(g_bshk3);
999            // Memory-efficient scan: a custom recompute backward (saves only the
1000            // leaf inputs) instead of retaining the scan's intermediates. Equal
1001            // to [`quat_cumprod`] on values and gradients (asserted in tests).
1002            let (cum_bshk4, final_bhk4) = crate::mamba3::quat_scan::quat_cumprod_recalculated(
1003                q_step_bshk4,
1004                Some(prev_q_bhk4),
1005            );
1006            // Renormalise the prefixes. A product of unit quaternions is a unit
1007            // quaternion in exact arithmetic, but the scan composes each prefix
1008            // out of `⌈log₂ L⌉` multiplies, so the norm drifts — negligibly in
1009            // f32, by ~1% over a long f16 sequence, and a non-unit rotation
1010            // rescales B/C instead of only turning them. `step` already
1011            // normalises every step; this is the chunkwise counterpart, and it
1012            // keeps the two numerically alike as well as exactly orthogonal.
1013            let cum_bshk4 = quat_normalize(cum_bshk4);
1014            let over_mimo = |q_bshj4: Tensor<5>| {
1015                q_bshj4
1016                    .unsqueeze_dim::<6>(2)
1017                    .expand([batch, sequence, mimo_rank, nheads, blocks, 4])
1018            };
1019            // B̄ = P⁻¹B: rotate by the inverse cumulative rotation, per block,
1020            // broadcast over the mimo_rank axis.
1021            let (b, c) = match kind {
1022                RotationKind::Rotor4D => {
1023                    // P(v) = Q v T̄  ⇒  P⁻¹(v) = Q* v T (conjugate on the left
1024                    // factor only).
1025                    let (left, right) = split_rotor(cum_bshk4);
1026                    let ql = over_mimo(quat_conj(left));
1027                    let qr = over_mimo(right);
1028                    (
1029                        rotate_blocks_two_sided_partial::<5, 6>(
1030                            b_bsmhr,
1031                            ql.clone(),
1032                            qr.clone(),
1033                            rope_width,
1034                        ),
1035                        rotate_blocks_two_sided_partial::<5, 6>(c_bsmhr, ql, qr, rope_width),
1036                    )
1037                }
1038                _ => {
1039                    let conj_bsmhj4 = over_mimo(quat_conj(cum_bshk4));
1040                    (
1041                        rotate_blocks_partial::<5, 6>(b_bsmhr, conj_bsmhj4.clone(), rope_width),
1042                        rotate_blocks_partial::<5, 6>(c_bsmhr, conj_bsmhj4, rope_width),
1043                    )
1044                }
1045            };
1046            let final_bhk4 = quat_normalize(final_bhk4);
1047            let state = match kind {
1048                RotationKind::Rotor4D => RotationState::Rotor(final_bhk4),
1049                _ => RotationState::Quaternion(final_bhk4),
1050            };
1051            (b, c, state)
1052        }
1053    }
1054}

1056/// Single-token counterpart of [`rotate_bc_forward`] for the recurrent `step`.
1057///
1058/// # Shapes
1059/// - `rot_ba`  : `[batch, num_rotation_channels]`, `None` for Real1D.
1060/// - `dt_bh`   : `[batch, nheads]`.
1061/// - `b_bmhr` / `c_bmhr` : `[batch, mimo_rank, nheads, state_rank]`.
1062pub fn rotate_bc_step(
1063    rot_ba: Option<Tensor<2>>,
1064    dt_bh: Tensor<2>,
1065    prev: RotationState,
1066    b_bmhr: Tensor<4>,
1067    c_bmhr: Tensor<4>,
1068    spec: RotationSpec,
1069) -> (Tensor<4>, Tensor<4>, RotationState) {
1070    let [batch, mimo_rank, nheads, _state_rank] = b_bmhr.dims();
1071    let RotationSpec {
1072        kind,
1073        rope_dim,
1074        range,
1075    } = spec;
1076    let rot = |r: Option<Tensor<2>>| r.expect("a rotating kind projects rotation channels");
1077    match kind {
1078        RotationKind::Real1D => (b_bmhr, c_bmhr, prev.expect_real()),
1079        RotationKind::Complex2D => {
1080            let rot_ba = rot(rot_ba);
1081            let prev_angle_bha = prev.angle();
1082            let num_rope_angles = prev_angle_bha.dims()[2];
1083            let raw_angle_bha = angle_increment::<2, 3>(rot_ba, dt_bh, range);
1084            let new_cum_angle_bha = wrap_angle(prev_angle_bha + raw_angle_bha);
1085            let new_cum_angle_bmha = new_cum_angle_bha.clone().unsqueeze_dim::<4>(1).expand([
1086                batch,
1087                mimo_rank,
1088                nheads,
1089                num_rope_angles,
1090            ]);
1091            let rotate_pairwise = mimo_rank == 1;
1092            let b = apply_rope_partial::<4>(
1093                b_bmhr,
1094                new_cum_angle_bmha.clone(),
1095                rope_dim,
1096                rotate_pairwise,
1097            );
1098            let c = apply_rope_partial::<4>(c_bmhr, new_cum_angle_bmha, rope_dim, rotate_pairwise);
1099            (b, c, RotationState::Angle(new_cum_angle_bha))
1100        }
1101        RotationKind::Quaternion4D | RotationKind::Rotor4D => {
1102            let (prev_q_bhk4, blocks) = prev.quat_stack(kind);
1103            let stack = prev_q_bhk4.dims()[2];
1104            assert_eq!(rope_dim, blocks * 4, "cache/block rotation width mismatch");
1105            let rope_width = rope_dim;
1106            // The same bounded generator as `rotate_bc_forward` (see the note there).
1107            let g_bhk3 = generator_increment::<2, 3, 4>(rot(rot_ba), dt_bh, stack, range);
1108            let q_step_bhk4 = quat_from_scaled_axis::<4>(g_bhk3);
1109            // Single step: Qₜ = qₜ ⊗ Qₜ₋₁ — and, stacked alongside it for
1110            // Rotor4D, Tₜ = pₜ ⊗ Tₜ₋₁ (the same left fold, see [`RotationState::Rotor`]).
1111            let new_q_bhk4 = quat_normalize(quat_mul(q_step_bhk4, prev_q_bhk4));
1112            let over_mimo = |q_bhj4: Tensor<4>| {
1113                q_bhj4
1114                    .unsqueeze_dim::<5>(1)
1115                    .expand([batch, mimo_rank, nheads, blocks, 4])
1116            };
1117            match kind {
1118                RotationKind::Rotor4D => {
1119                    let (left, right) = split_rotor(new_q_bhk4.clone());
1120                    let ql = over_mimo(quat_conj(left));
1121                    let qr = over_mimo(right);
1122                    let b = rotate_blocks_two_sided_partial::<4, 5>(
1123                        b_bmhr,
1124                        ql.clone(),
1125                        qr.clone(),
1126                        rope_width,
1127                    );
1128                    let c = rotate_blocks_two_sided_partial::<4, 5>(c_bmhr, ql, qr, rope_width);
1129                    (b, c, RotationState::Rotor(new_q_bhk4))
1130                }
1131                _ => {
1132                    let conj_bmhj4 = over_mimo(quat_conj(new_q_bhk4.clone()));
1133                    let b = rotate_blocks_partial::<4, 5>(b_bmhr, conj_bmhj4.clone(), rope_width);
1134                    let c = rotate_blocks_partial::<4, 5>(c_bmhr, conj_bmhj4, rope_width);
1135                    (b, c, RotationState::Quaternion(new_q_bhk4))
1136                }
1137            }
1138        }
1139    }
1140}
