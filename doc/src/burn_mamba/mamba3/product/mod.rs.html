1//! # MambaProduct — `u` micro-steps per token
2//!
3//! `u` full Mamba-3 recurrence steps per token, each with its own projected
4//! `x`, `B`, `Δ`, `A`, `λ` and rotation, read on the last. Selected by
5//! [`Mamba3Config::micro_steps`](crate::mamba3::mamba3::Mamba3Config::micro_steps)
6//! (`u`); `u = 1` is stock Mamba-3, byte for byte.
7//!
8//! ## The dial, and whose it is
9//!
10//! The *dial* is DeltaProduct's (*Improving State-Tracking in Linear RNNs via
11//! Householder Products*, Siems, Carstensen, Zela, Hutter, Pontil, Grazzi;
12//! 2025): `u` first-order steps per token, buying transition expressiveness at
13//! `u`× the recurrence work and **no** extra state. The *mechanism* is not, and
14//! the difference is worth stating once, because it decides everything below.
15//!
16//! Write both as `u` steps of an online learner, `Mₜ = ∏ⱼ (I − ηⱼ ∇²Lⱼ)`. The
17//! two families turn different dials in it:
18//!
19//! - **DeltaProduct turns the curvature.** Its `∇²Lⱼ = kⱼkⱼᵀ` is rank-one and
20//!   direction-dependent, so factors with different `kⱼ` do not commute and the
21//!   product leaves the real axis (Cartan–Dieudonné; the paper's own condition
22//!   is that *both* `βⱼ > 1`, i.e. both micro-steps overshoot).
23//! - **Mamba-3 turns the step size.** Its curvature is isotropic (`∇²L = ρI`,
24//!   the scalar transition), so every factor is a *scalar* — and scalars
25//!   commute. No number of micro-steps can rotate a Mamba transition; the
26//!   rotation has to come from `ηⱼ` leaving `ℝ`, which is exactly what
27//!   [`RotationKind`](crate::mamba3::rotation::RotationKind) is.
28//!
29//! So DeltaProduct's mechanism has no instance here (with isotropic curvature
30//! `u` micro-writes under a shared transition provably collapse into a rank-`u`
31//! write, which is [`mimo_rank`](crate::mamba3::mamba3::Mamba3Config::mimo_rank)),
32//! and this is the same construction reached by the other dial. `info/rotation-as-optimization.md`
33//! derives the above and everything in the table below.
34//!
35//! Mamba-3's transition is `αₜ Rₜ` (§*Complex-Valued SSMs*): a scalar decay
36//! times a rotation. Running `u` micro-steps per token makes the per-token
37//! transition
38//!
39//! ```text
40//!   Mₜ = (∏ⱼ αₜ,ⱼ) · Rₜ,ᵤ ⋯ Rₜ,₁
41//! ```
42//!
43//! and the write a sum of `u` outer products, each landing at its own point of
44//! that rotation product. What `u` buys therefore depends entirely on the
45//! [`RotationKind`](crate::mamba3::rotation::RotationKind), and the answer is
46//! sharp:
47//!
48//! | kind | the product `Rₜ,ᵤ⋯Rₜ,₁` | what `u > 1` buys |
49//! |---|---|---|
50//! | [`Real1D`] | `I` | the write only: `u` staggered rank-1 writes per token |
51//! | [`Complex2D`] | `R(Σⱼ θⱼ)`, abelian | `u`× the per-token **angle reach**, plus the staggered write |
52//! | [`Quaternion4D`] / [`Rotor4D`] | a genuinely non-commuting product | a per-token transition **no single step can express** |
53//!
54//! [`Real1D`]: crate::mamba3::rotation::RotationKind::Real1D
55//! [`Complex2D`]: crate::mamba3::rotation::RotationKind::Complex2D
56//! [`Quaternion4D`]: crate::mamba3::rotation::RotationKind::Quaternion4D
57//! [`Rotor4D`]: crate::mamba3::rotation::RotationKind::Rotor4D
58//!
59//! Three consequences worth stating outright, because they decide when the dial
60//! is worth turning:
61//!
62//! - **On a real transition it is not a new transition, only a wider write.**
63//!   With [`Real1D`] the step size is real too, so every factor is a *real*
64//!   scalar, scalars commute, and the `u` micro-writes collapse into one
65//!   rank-`u` update with decay-staggered
66//!   weights. That is the *sequential* reading of the cell
67//!   [`mimo_rank`](crate::mamba3::mamba3::Mamba3Config::mimo_rank) occupies
68//!   *jointly* — an epoch of `u` samples versus a minibatch of `M` — and it is
69//!   why this dial lives on Mamba-3 and not on Mamba-2, whose transition is
70//!   scalar by construction and for which `u` would buy nothing at all.
71//! - **On the abelian rotation it lifts a bound the block otherwise cannot
72//!   cross.** One step turns by at most
73//!   [`rotation_range`](crate::mamba3::mamba3::Mamba3Config::rotation_range)`·π·Δ`,
74//!   and a rotation *at* that bound sits on `tanh`'s asymptote where the f32
75//!   gradient is exactly zero — so the half-turn state-tracking wants is
76//!   unreachable by descent at `rotation_range = 1`. `u` micro-rotations, each
77//!   comfortably inside the bound, compose to `u`× the reach with live
78//!   gradients at every factor. Note what pays for it: the token gets `u`
79//!   *full-size* steps, i.e. its effective interval is inflated `u`×, not
80//!   subdivided. The consistent alternative (`Δⱼ = Δ/u`, same per-token
81//!   transition, buying only the staggered writes and the ordering below) stays
82//!   inside the model's reach — `dt_limit` has no lower floor by default — so
83//!   this is a superset of it, not a substitute.
84//! - **On the non-abelian rotations it is DeltaProduct's argument reached by
85//!   the other dial.** The factors do not commute, so the product is not any
86//!   single bounded step; `u` is the number of generators the token may
87//!   compose, and the group is given directly rather than factored into
88//!   reflections.
89//!
90//! ## How it is evaluated
91//!
92//! Not with a new kernel — the micro-steps are folded into the **sequence**.
93//! The in-projection widens exactly the per-micro-step segments,
94//!
95//! ```text
96//!   [ z | x·u | B·u | C | Δ·u | A·u | λ·u | rotation·u ]
97//! ```
98//!
99//! and [`unfold_micro_bs`] reinterprets each `u`-wide segment as `u` consecutive
100//! sequence positions, so the SSD core, the trapezoid, the rotation scan, the
101//! chunking and the caches all run unchanged on a sequence of length
102//! `sequence · u`. Two placements make that exactly the recurrence above:
103//!
104//! - **The read `C` sits on the last micro-step.** It is
105//!   [`repeat_micro_bs`]-broadcast across the group so the last position sees
106//!   the correct cumulative rotation; the other positions' outputs are sliced
107//!   away by [`last_micro5`], so what they hold never matters.
108//! - **`z`, the `D` skip and the output gate are per token**, the skip taking
109//!   the last micro-step's `x` — the value the readout is contemporaneous with.
110//!
111//! Everything else is per micro-step, including the decay. Mamba has no forget
112//! gate separate from its step size — `α = exp(ΔA)` and `Δ` also weights the
113//! write and paces the rotation — so DeltaProduct's "forget gate on micro-step
114//! 0" has no faithful analogue here, and pinning `α ≡ 1` on the interior
115//! micro-steps would silence the rotation with it. A scalar decay composes
116//! either way (`∏ⱼ αₜ,ⱼ` is one decay per token), so the uniform placement costs
117//! nothing and keeps every micro-step a plain Mamba-3 step.
118//!
119//! ## Caches, and what does *not* change
120//!
121//! Nothing. The state is one `[batch, nheads, per_head_dim, state_rank]` matrix
122//! at every `u`: like DeltaProduct, this buys transition expressiveness, not
123//! memory. The trapezoid's previous-token taps (`k_state`, `v_state`) and the
124//! rotation accumulator hold the **last micro-step** of the last token, which is
125//! precisely the position the next call's first micro-step follows — so a
126//! chunked prefill splits at token boundaries exactly as it did before.
127//!
128//! One thing genuinely does move: the trapezoid's two taps now straddle
129//! *micro-steps* rather than tokens, i.e. the 2-tap FIR filter on the state
130//! input runs at the finer rate. That is what "the recurrence is the folded
131//! sequence" means, and it is what keeps `forward` and `step` in exact
132//! agreement.
133//!
134//! ## The one thing `u > 1` takes away
135//!
136//! [`Mamba3::step_infinite`](crate::mamba3::mamba3::Mamba3::step_infinite) —
137//! the stationary output under a constant token — **exists only for the abelian
138//! kinds** once
139//! `u > 1`. The readout at token `t` sees a write from token `t − n` through the
140//! relative rotation `P⁻ᵗ Qⱼ Pᵗ⁻ⁿ⁻¹`, where `P = Rᵤ⋯R₁` is the per-token product
141//! and `Qⱼ = Rⱼ⋯R₁` the partial one. That collapses to a function of `n` alone
142//! iff `Qⱼ` commutes with `P`. When it does not — [`Quaternion4D`],
143//! [`Rotor4D`] — the conjugation `P⁻ᵗQⱼPᵗ` keeps turning with `t` and the output
144//! is almost-periodic rather than convergent: there is no limit to return, which
145//! is a fact about the recurrence and not a gap in the implementation.
146//!
147//! ## Notation
148//!
149//! `u` is `micro_steps`. In the folded region of `forward` the shape letter `s`
150//! counts **micro-steps**, not tokens; a name still at token resolution says so
151//! (`tokens`). See the [`mamba3`](crate::mamba3::mamba3) module header for the
152//! rest of the dimension keys.

156/// Fold a `u`-wide in-projection segment into the sequence axis.
157///
158/// The projection lays a token's micro-steps out contiguously
159/// (`channel = j·width + c`), which is already the memory order of
160/// `[batch, sequence, u, width]` — so the fold is a single reshape and never
161/// moves data.
162///
163/// # Shapes
164/// - `t_bsW` : `[batch, sequence, u · width]`
165/// - out     : `[batch, sequence · u, width]`
166#[allow(non_snake_case)]
167pub fn unfold_micro_bs(t_bsW: Tensor<3>, micro_steps: usize) -> Tensor<3> {
168    let [batch, sequence, fused] = t_bsW.dims();
169    assert_eq!(
170        fused % micro_steps,
171        0,
172        "a per-micro-step segment is a multiple of micro_steps wide"
173    );
174    t_bsW.reshape([batch, sequence * micro_steps, fused / micro_steps])
175}
176
177/// [`unfold_micro_bs`] for a single token: split the micro-steps onto an axis of
178/// their own.
179///
180/// # Shapes
181/// - `t_bW` : `[batch, u · width]`
182/// - out    : `[batch, u, width]`
183#[allow(non_snake_case)]
184pub fn unfold_micro_b(t_bW: Tensor<2>, micro_steps: usize) -> Tensor<3> {
185    let [batch, fused] = t_bW.dims();
186    assert_eq!(
187        fused % micro_steps,
188        0,
189        "a per-micro-step segment is a multiple of micro_steps wide"
190    );
191    t_bW.reshape([batch, micro_steps, fused / micro_steps])
192}

194/// Broadcast a **per-token** projection across the token's micro-steps, so it
195/// can ride the folded sequence alongside the per-micro-step ones.
196///
197/// Used for the read `C`: only its last-micro-step copy is ever read (the
198/// others' outputs are dropped by [`last_micro5`]), but that copy has to sit at
199/// the last position to pick up the right cumulative rotation.
200///
201/// # Shapes
202/// - `t_bsw` : `[batch, sequence, width]`
203/// - out     : `[batch, sequence · u, width]`
204pub fn repeat_micro_bs(t_bsw: Tensor<3>, micro_steps: usize) -> Tensor<3> {
205    let [batch, sequence, width] = t_bsw.dims();
206    if micro_steps == 1 {
207        return t_bsw;
208    }
209    t_bsw
210        .unsqueeze_dim::<4>(2)
211        .repeat_dim(2, micro_steps)
212        .reshape([batch, sequence * micro_steps, width])
213}
214
215/// Keep each token's **last** micro-step — the position the readout happens at —
216/// collapsing the folded sequence back to token resolution.
217///
218/// # Shapes
219/// - `t_bSmhp` : `[batch, sequence · u, mimo_rank, nheads, per_head_dim]`
220/// - out       : `[batch, sequence, mimo_rank, nheads, per_head_dim]`
221#[allow(non_snake_case)]
222pub fn last_micro5(t_bSmhp: Tensor<5>, micro_steps: usize) -> Tensor<5> {
223    let [batch, folded, mimo_rank, nheads, per_head_dim] = t_bSmhp.dims();
224    if micro_steps == 1 {
225        return t_bSmhp;
226    }
227    let sequence = folded / micro_steps;
228    t_bSmhp
229        .reshape([
230            batch,
231            sequence,
232            micro_steps,
233            mimo_rank,
234            nheads,
235            per_head_dim,
236        ])
237        .narrow(2, micro_steps - 1, 1)
238        .squeeze_dim(2)
239}
240
241/// [`last_micro5`] one rank down — the value stream feeding the `D` skip.
242///
243/// # Shapes
244/// - `t_bShp` : `[batch, sequence · u, nheads, per_head_dim]`
245/// - out      : `[batch, sequence, nheads, per_head_dim]`
246#[allow(non_snake_case)]
247pub fn last_micro4(t_bShp: Tensor<4>, micro_steps: usize) -> Tensor<4> {
248    let [batch, folded, nheads, per_head_dim] = t_bShp.dims();
249    if micro_steps == 1 {
250        return t_bShp;
251    }
252    let sequence = folded / micro_steps;
253    t_bShp
254        .reshape([batch, sequence, micro_steps, nheads, per_head_dim])
255        .narrow(2, micro_steps - 1, 1)
256        .squeeze_dim(2)
257}
