1//! # MambaProduct — `u` micro-steps per token
2//!
3//! *DeltaProduct: Improving State-Tracking in Linear RNNs via Householder
4//! Products* (Siems, Carstensen, Zela, Hutter, Pontil, Grazzi; 2025), carried
5//! over to the Mamba-3 recurrence. Selected by
6//! [`Mamba3Config::micro_steps`](crate::mamba3::mamba3::Mamba3Config::micro_steps)
7//! (`u`); `u = 1` is stock Mamba-3, byte for byte.
8//!
9//! ## What DeltaProduct does, and what carries over
10//!
11//! DeltaNet's transition is one generalised Householder `I − βkkᵀ`, so one step
12//! moves the state along one direction. DeltaProduct takes `u` delta-rule
13//! micro-steps per token, making the transition a **product**
14//! `∏ⱼ (I − βⱼkⱼkⱼᵀ)`, which by Cartan–Dieudonné reaches every element of the
15//! orthogonal group of a `u`-dimensional subspace — a direct dial on how much
16//! group structure one transition can track, at `u`× the recurrence work and no
17//! extra state.
18//!
19//! Mamba-3's transition is `αₜ Rₜ` (§*Complex-Valued SSMs*): a scalar decay
20//! times a rotation. Running `u` micro-steps per token makes the per-token
21//! transition
22//!
23//! ```text
24//!   Mₜ = (∏ⱼ αₜ,ⱼ) · Rₜ,ᵤ ⋯ Rₜ,₁
25//! ```
26//!
27//! and the write a sum of `u` outer products, each landing at its own point of
28//! that rotation product. What `u` buys therefore depends entirely on the
29//! [`RotationKind`](crate::mamba3::rotation::RotationKind), and the answer is
30//! sharp:
31//!
32//! | kind | the product `Rₜ,ᵤ⋯Rₜ,₁` | what `u > 1` buys |
33//! |---|---|---|
34//! | [`Real1D`] | `I` | the write only: `u` staggered rank-1 writes per token |
35//! | [`Complex2D`] | `R(Σⱼ θⱼ)`, abelian | `u`× the per-token **angle reach**, plus the staggered write |
36//! | [`Quaternion4D`] / [`Rotor4D`] | a genuinely non-commuting product | a per-token transition **no single step can express** |
37//!
38//! [`Real1D`]: crate::mamba3::rotation::RotationKind::Real1D
39//! [`Complex2D`]: crate::mamba3::rotation::RotationKind::Complex2D
40//! [`Quaternion4D`]: crate::mamba3::rotation::RotationKind::Quaternion4D
41//! [`Rotor4D`]: crate::mamba3::rotation::RotationKind::Rotor4D
42//!
43//! Three consequences worth stating outright, because they decide when the dial
44//! is worth turning:
45//!
46//! - **On a real transition it is not a new transition, only a wider write.**
47//!   With [`Real1D`] every factor is a scalar, scalars commute, and the `u`
48//!   micro-writes collapse into one rank-`u` update with decay-staggered
49//!   weights. That is the *sequential* reading of the cell
50//!   [`mimo_rank`](crate::mamba3::mamba3::Mamba3Config::mimo_rank) occupies
51//!   *jointly* — an epoch of `u` samples versus a minibatch of `M` — and it is
52//!   why this dial lives on Mamba-3 and not on Mamba-2, whose transition is
53//!   scalar by construction and for which `u` would buy nothing at all.
54//! - **On the abelian rotation it lifts a bound the block otherwise cannot
55//!   cross.** One step turns by at most
56//!   [`rotation_range`](crate::mamba3::mamba3::Mamba3Config::rotation_range)`·π·Δ`,
57//!   and a rotation *at* that bound sits on `tanh`'s asymptote where the f32
58//!   gradient is exactly zero — so the half-turn state-tracking wants is
59//!   unreachable by descent at `rotation_range = 1`. `u` micro-rotations, each
60//!   comfortably inside the bound, compose to `u`× the reach with live
61//!   gradients at every factor.
62//! - **On the non-abelian rotations it is DeltaProduct's own argument,
63//!   verbatim.** The factors do not commute, so the product is not any single
64//!   bounded step; `u` is the number of generators the token may compose.
65//!
66//! ## How it is evaluated
67//!
68//! Not with a new kernel — the micro-steps are folded into the **sequence**.
69//! The in-projection widens exactly the per-micro-step segments,
70//!
71//! ```text
72//!   [ z | x·u | B·u | C | Δ·u | A·u | λ·u | rotation·u ]
73//! ```
74//!
75//! and [`unfold_micro_bs`] reinterprets each `u`-wide segment as `u` consecutive
76//! sequence positions, so the SSD core, the trapezoid, the rotation scan, the
77//! chunking and the caches all run unchanged on a sequence of length
78//! `sequence · u`. Two placements make that exactly the recurrence above:
79//!
80//! - **The read `C` sits on the last micro-step.** It is
81//!   [`repeat_micro_bs`]-broadcast across the group so the last position sees
82//!   the correct cumulative rotation; the other positions' outputs are sliced
83//!   away by [`last_micro5`], so what they hold never matters.
84//! - **`z`, the `D` skip and the output gate are per token**, the skip taking
85//!   the last micro-step's `x` — the value the readout is contemporaneous with.
86//!
87//! Everything else is per micro-step, including the decay. Mamba has no forget
88//! gate separate from its step size — `α = exp(ΔA)` and `Δ` also weights the
89//! write and paces the rotation — so DeltaProduct's "forget gate on micro-step
90//! 0" has no faithful analogue here, and pinning `α ≡ 1` on the interior
91//! micro-steps would silence the rotation with it. A scalar decay composes
92//! either way (`∏ⱼ αₜ,ⱼ` is one decay per token), so the uniform placement costs
93//! nothing and keeps every micro-step a plain Mamba-3 step.
94//!
95//! ## Caches, and what does *not* change
96//!
97//! Nothing. The state is one `[batch, nheads, per_head_dim, state_rank]` matrix
98//! at every `u`: like DeltaProduct, this buys transition expressiveness, not
99//! memory. The trapezoid's previous-token taps (`k_state`, `v_state`) and the
100//! rotation accumulator hold the **last micro-step** of the last token, which is
101//! precisely the position the next call's first micro-step follows — so a
102//! chunked prefill splits at token boundaries exactly as it did before.
103//!
104//! One thing genuinely does move: the trapezoid's two taps now straddle
105//! *micro-steps* rather than tokens, i.e. the 2-tap FIR filter on the state
106//! input runs at the finer rate. That is what "the recurrence is the folded
107//! sequence" means, and it is what keeps `forward` and `step` in exact
108//! agreement.
109//!
110//! ## The one thing `u > 1` takes away
111//!
112//! [`Mamba3::step_infinite`](crate::mamba3::mamba3::Mamba3::step_infinite) —
113//! the stationary output under a constant token — **exists only for the abelian
114//! kinds** once
115//! `u > 1`. The readout at token `t` sees a write from token `t − n` through the
116//! relative rotation `P⁻ᵗ Qⱼ Pᵗ⁻ⁿ⁻¹`, where `P = Rᵤ⋯R₁` is the per-token product
117//! and `Qⱼ = Rⱼ⋯R₁` the partial one. That collapses to a function of `n` alone
118//! iff `Qⱼ` commutes with `P`. When it does not — [`Quaternion4D`],
119//! [`Rotor4D`] — the conjugation `P⁻ᵗQⱼPᵗ` keeps turning with `t` and the output
120//! is almost-periodic rather than convergent: there is no limit to return, which
121//! is a fact about the recurrence and not a gap in the implementation.
122//!
123//! ## Notation
124//!
125//! `u` is `micro_steps`. In the folded region of `forward` the shape letter `s`
126//! counts **micro-steps**, not tokens; a name still at token resolution says so
127//! (`tokens`). See the [`mamba3`](crate::mamba3::mamba3) module header for the
128//! rest of the dimension keys.

132/// Fold a `u`-wide in-projection segment into the sequence axis.
133///
134/// The projection lays a token's micro-steps out contiguously
135/// (`channel = j·width + c`), which is already the memory order of
136/// `[batch, sequence, u, width]` — so the fold is a single reshape and never
137/// moves data.
138///
139/// # Shapes
140/// - `t_bsW` : `[batch, sequence, u · width]`
141/// - out     : `[batch, sequence · u, width]`
142#[allow(non_snake_case)]
143pub fn unfold_micro_bs(t_bsW: Tensor<3>, micro_steps: usize) -> Tensor<3> {
144    let [batch, sequence, fused] = t_bsW.dims();
145    assert_eq!(
146        fused % micro_steps,
147        0,
148        "a per-micro-step segment is a multiple of micro_steps wide"
149    );
150    t_bsW.reshape([batch, sequence * micro_steps, fused / micro_steps])
151}
152
153/// [`unfold_micro_bs`] for a single token: split the micro-steps onto an axis of
154/// their own.
155///
156/// # Shapes
157/// - `t_bW` : `[batch, u · width]`
158/// - out    : `[batch, u, width]`
159#[allow(non_snake_case)]
160pub fn unfold_micro_b(t_bW: Tensor<2>, micro_steps: usize) -> Tensor<3> {
161    let [batch, fused] = t_bW.dims();
162    assert_eq!(
163        fused % micro_steps,
164        0,
165        "a per-micro-step segment is a multiple of micro_steps wide"
166    );
167    t_bW.reshape([batch, micro_steps, fused / micro_steps])
168}

170/// Broadcast a **per-token** projection across the token's micro-steps, so it
171/// can ride the folded sequence alongside the per-micro-step ones.
172///
173/// Used for the read `C`: only its last-micro-step copy is ever read (the
174/// others' outputs are dropped by [`last_micro5`]), but that copy has to sit at
175/// the last position to pick up the right cumulative rotation.
176///
177/// # Shapes
178/// - `t_bsw` : `[batch, sequence, width]`
179/// - out     : `[batch, sequence · u, width]`
180pub fn repeat_micro_bs(t_bsw: Tensor<3>, micro_steps: usize) -> Tensor<3> {
181    let [batch, sequence, width] = t_bsw.dims();
182    if micro_steps == 1 {
183        return t_bsw;
184    }
185    t_bsw
186        .unsqueeze_dim::<4>(2)
187        .repeat_dim(2, micro_steps)
188        .reshape([batch, sequence * micro_steps, width])
189}
190
191/// Keep each token's **last** micro-step — the position the readout happens at —
192/// collapsing the folded sequence back to token resolution.
193///
194/// # Shapes
195/// - `t_bSmhp` : `[batch, sequence · u, mimo_rank, nheads, per_head_dim]`
196/// - out       : `[batch, sequence, mimo_rank, nheads, per_head_dim]`
197#[allow(non_snake_case)]
198pub fn last_micro5(t_bSmhp: Tensor<5>, micro_steps: usize) -> Tensor<5> {
199    let [batch, folded, mimo_rank, nheads, per_head_dim] = t_bSmhp.dims();
200    if micro_steps == 1 {
201        return t_bSmhp;
202    }
203    let sequence = folded / micro_steps;
204    t_bSmhp
205        .reshape([
206            batch,
207            sequence,
208            micro_steps,
209            mimo_rank,
210            nheads,
211            per_head_dim,
212        ])
213        .narrow(2, micro_steps - 1, 1)
214        .squeeze_dim(2)
215}
216
217/// [`last_micro5`] one rank down — the value stream feeding the `D` skip.
218///
219/// # Shapes
220/// - `t_bShp` : `[batch, sequence · u, nheads, per_head_dim]`
221/// - out      : `[batch, sequence, nheads, per_head_dim]`
222#[allow(non_snake_case)]
223pub fn last_micro4(t_bShp: Tensor<4>, micro_steps: usize) -> Tensor<4> {
224    let [batch, folded, nheads, per_head_dim] = t_bShp.dims();
225    if micro_steps == 1 {
226        return t_bShp;
227    }
228    let sequence = folded / micro_steps;
229    t_bShp
230        .reshape([batch, sequence, micro_steps, nheads, per_head_dim])
231        .narrow(2, micro_steps - 1, 1)
232        .squeeze_dim(2)
233}
