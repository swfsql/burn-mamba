1//! # Mamba-3
2//!
3//! Mamba-3 extends Mamba-2 with four independent additions. Each one works
4//! alone or with the others:
5//!
6//! 1. **Trapezoidal discretisation** of the recurrence.
7//! 2. A **complex-valued state transition**, applied as a **data-dependent
8//!    rotation** of the B/C projections
9//!    ([`rotation`](crate::mamba3::rotation)). This is a re-factoring of the
10//!    transition, *not* a positional encoding.
11//! 3. **MIMO** (multiple-input multiple-output) rank expansion.
12//! 4. **MambaProduct** ([`product`](crate::mamba3::product)):
13//!    [`micro_steps`](crate::mamba3::mamba3::Mamba3Config::micro_steps)
14//!    micro-steps per token, so the transition of one token is a
15//!    **product** of `u` micro-steps. The micro-steps fold into the write
16//!    axis, so MambaProduct needs no new kernel.
17//!
18//! See [`mamba3`](crate::mamba3::mamba3) for the full combined math.
19//!
20//! ## Two SSD pathways
21//!
22//! Two interchangeable pathways compute the trapezoidal recurrence. The
23//! **cache variant** that the caller supplies selects one at runtime:
24//!
25//! - [`double_ssd`](crate::mamba3::double_ssd) — one standard SSD call per
26//!   trapezoid term: one for the current sample, plus one per `β` tap
27//!   ([`tap_pattern`](crate::mamba3::tap_pattern)). That is **two** calls at the
28//!   default and three under a two-tap pattern. It is simple and easy to
29//!   verify, but it uses ~2× the intra-chunk memory (~3× at two taps).
30//! - [`single_ssd`](crate::mamba3::single_ssd) — **one** SSD call in the
31//!   official-kernel form, for every tap pattern. It uses ≈ half the training
32//!   memory of the double pathway at the default, and less when there are more
33//!   taps. It carries the accumulator, which differs from the state
34//!   mid-sequence.
35//!
36//! [`cache`](crate::mamba3::cache) holds the enum that selects the pathway,
37//! and the frame cache that both cache types keep.
38//! [`ssd_path`](crate::mamba3::ssd_path) selects the pathway-agnostic
39//! *SSD path* (Minimal / Serial / SerialRecalculated).
40//!
41//! ## The tap pattern of the trapezoid
42//!
43//! [`tap_pattern`](crate::mamba3::tap_pattern) names the earlier sample(s) that the
44//! second tap of the write reads. This choice exists only at `u > 1`, and it
45//! changes the algorithm *and* the cache. Four of the six members have one lag
46//! each ([`tap_lag`](crate::mamba3::tap_pattern::TapPattern::tap_lag)):
47//!
48//! - the default
49//!   [`HorizontalCarryOver`](crate::mamba3::tap_pattern::TapPattern::HorizontalCarryOver)
50//!   (lag 1),
51//! - [`Vertical`](crate::mamba3::tap_pattern::TapPattern::Vertical) (lag `u`),
52//!   which is equal to the default at `u = 1`,
53//! - [`HorizontalInToken`](crate::mamba3::tap_pattern::TapPattern::HorizontalInToken)
54//!   (lag 1, and the tap closes at token boundaries),
55//! - the tapless [`None`](crate::mamba3::tap_pattern::TapPattern::None).
56//!
57//! The two other members have both lags. A second per-head mass mixes them.
58//!
59//! ## Positive systems beside the plant
60//!
61//! [`positive`](crate::mamba3::positive) adds a per-head scalar system. It
62//! reads only the inputs and sets the coefficients of the plant:
63//!
64//! - a Kalman gain ([`Gain`](crate::mamba3::positive::Gain)) *computes* the
65//!   decay from an accumulated precision,
66//! - a soft max-plus register ([`Tropical`](crate::mamba3::positive::Tropical))
67//!   adds to the readout.
68//!
69//! Both are nonnegative 2×2 matrix recurrences, scanned in log coordinates.
70//! Each has one cache field, and neither changes a kernel.
