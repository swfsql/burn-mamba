1//! # Mamba-3
2//!
3//! Mamba-3 extends Mamba-2 with four independent additions. Each one works
4//! alone or with the others:
5//!
6//! 1. **Trapezoidal discretisation** of the recurrence.
7//! 2. A **complex-valued state transition**, applied as a **data-dependent
8//!    rotation** of the B/C projections
9//!    ([`rotation`](crate::mamba3::rotation)). This is a re-factoring of the
10//!    transition, *not* a positional encoding.
11//! 3. **MIMO** (multiple-input multiple-output) rank expansion.
12//! 4. **MambaProduct** ([`product`](crate::mamba3::product)):
13//!    [`micro_steps`](crate::mamba3::mamba3::Mamba3Config::micro_steps)
14//!    micro-steps per token, so the transition of one token is a
15//!    **product** of `u` micro-steps. The micro-steps fold into the write
16//!    axis, so MambaProduct needs no new kernel.
17//!
18//! See [`mamba3`](crate::mamba3::mamba3) for the full combined math.
19//!
20//! ## Two SSD pathways
21//!
22//! Two interchangeable pathways compute the trapezoidal recurrence. The
23//! [`Pathway`](crate::mamba3::scan_options::Pathway) of the scan options
24//! selects one at runtime:
25//!
26//! - [`double_ssd`](crate::mamba3::double_ssd) — one standard SSD call per
27//!   trapezoid term: one for the current sample, plus one per `β` tap
28//!   ([`tap_pattern`](crate::mamba3::tap_pattern)). That is **two** calls at the
29//!   default and three under a two-tap pattern. It is simple and easy to
30//!   verify, but it uses ~2× the intra-chunk memory (~3× at two taps).
31//! - [`single_ssd`](crate::mamba3::single_ssd) — **one** SSD call in the
32//!   official-kernel form, for every tap pattern. It uses ≈ half the training
33//!   memory of the double pathway at the default, and less when there are more
34//!   taps. It carries the accumulator, which differs from the state
35//!   mid-sequence. It is the default.
36//!
37//! [`cache`](crate::mamba3::cache) holds the one cache type of both pathways,
38//! with its frame cache. [`scan_options`](crate::mamba3::scan_options) holds
39//! the scan options: the [SSD path](crate::ssd_path::SsdPath) (Minimal /
40//! Serial / SerialRecalculated), the chunk length and the pathway.
41//!
42//! ## The tap pattern of the trapezoid
43//!
44//! [`tap_pattern`](crate::mamba3::tap_pattern) names the earlier sample(s) that the
45//! second tap of the write reads. This choice exists only at `u > 1`, and it
46//! changes the algorithm *and* the cache. Four of the six members have one lag
47//! each ([`tap_lag`](crate::mamba3::tap_pattern::TapPattern::tap_lag)):
48//!
49//! - the default
50//!   [`HorizontalCarryOver`](crate::mamba3::tap_pattern::TapPattern::HorizontalCarryOver)
51//!   (lag 1),
52//! - [`Vertical`](crate::mamba3::tap_pattern::TapPattern::Vertical) (lag `u`),
53//!   which is equal to the default at `u = 1`,
54//! - [`HorizontalInToken`](crate::mamba3::tap_pattern::TapPattern::HorizontalInToken)
55//!   (lag 1, and the tap closes at token boundaries),
56//! - the tapless [`None`](crate::mamba3::tap_pattern::TapPattern::None).
57//!
58//! The two other members have both lags. A second per-head mass mixes them.
59//!
60//! ## Positive systems beside the plant
61//!
62//! [`positive`](crate::mamba3::positive) adds a per-head scalar system. It
63//! reads only the inputs and sets the coefficients of the plant:
64//!
65//! - a Kalman gain ([`Gain`](crate::mamba3::positive::Gain)) *computes* the
66//!   decay from an accumulated precision,
67//! - a soft max-plus register ([`Tropical`](crate::mamba3::positive::Tropical))
68//!   adds to the readout.
69//!
70//! Both are nonnegative 2×2 matrix recurrences, scanned in log coordinates.
71//! Each has one cache field, and neither changes a kernel.
