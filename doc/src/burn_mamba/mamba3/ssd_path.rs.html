1//! # Pathway-agnostic SSD algorithm selection (Mamba-3)
2//!
3//! [`Mamba3SsdPath`] selects the chunkwise SSD *algorithm* (Minimal / Serial /
4//! SerialRecalculated) and the chunk length. It is independent of the
5//! double-vs-single *pathway*, which the cache variant selects. It converts
6//! into the per-pathway path types with `From`, and
7//! [`Mamba3::forward`](crate::mamba3::mamba3::Mamba3::forward) sends it to the
8//! pathway of the cache.
9
10use crate::mamba3::prelude::*;
11
12/// Algorithm selection for the Mamba-3 chunkwise SSD.
13///
14/// This selects the chunkwise SSD *algorithm*. The cache variant selects the
15/// *pathway* (double- vs single-ssd, see
16/// [`crate::mamba3::cache::Mamba3Caches`]). [`Mamba3::forward`] converts this
17/// selection into the input bundle of that pathway
18/// ([`crate::mamba3::double_ssd::ssd::Mamba3DoubleSsdInput`] or
19/// [`crate::mamba3::single_ssd::ssd::Mamba3SingleSsdInput`]) and calls its
20/// `run`.
21///
22/// Each variant carries an optional chunk length. A larger value gives more
23/// intra-chunk GEMM work and a shorter inter-chunk scan. The optimal value is
24/// approximately `√(state_rank · per_head_dim)`, divided by the widening that
25/// `mimo_rank` and `micro_steps` already give the chunk (see
26/// [`Self::optimal_chunk_len`]). `None` uses that optimal value.
27///
28/// The default is [`Self::SerialRecalculated`] with an unset chunk length.
29#[derive(Debug, Clone)]
30pub enum Mamba3SsdPath {
31    /// Minimal/segsum SSD: mostly batched matmuls, with the autodiff backward.
32    ///
33    /// See [`crate::mamba3::double_ssd::ssd::Mamba3DoubleSsdInput::double_ssd_minimal`]
34    /// / [`crate::mamba3::single_ssd::ssd::Mamba3SingleSsdInput::single_ssd_minimal`].
35    /// For training, prefer [`Self::SerialRecalculated`]. This is the only path
36    /// that supports a learnable initial state.
37    Minimal(Option<usize>),
38
39    /// (Hybrid) serial SSD: a serial loop over the chunks plus batched
40    /// matmuls, with the autodiff backward.
41    ///
42    /// See [`crate::mamba3::double_ssd::ssd::Mamba3DoubleSsdInput::double_ssd_serial`]
43    /// / [`crate::mamba3::single_ssd::ssd::Mamba3SingleSsdInput::single_ssd_serial`].
44    /// For a memory-saving custom backward, see [`Self::SerialRecalculated`].
45    Serial(Option<usize>),
46
47    /// (Hybrid) serial SSD with a custom, memory-efficient backward. The
48    /// backward recomputes the forward intermediates instead of storing them.
49    ///
50    /// See [`crate::mamba3::double_ssd::ssd::Mamba3DoubleSsdInput::double_ssd_serial_recalculated`]
51    /// / [`crate::mamba3::single_ssd::ssd::Mamba3SingleSsdInput::single_ssd_serial_recalculated`].
52    /// For a plain autodiff backward, see [`Self::Serial`].
53    SerialRecalculated(Option<usize>),
54}
55
56impl Mamba3SsdPath {
57    /// Optimal chunk length, in **folded positions**: `√(state_rank ·
58    /// per_head_dim)` divided by `mimo_rank`, on the 32 grid, clamped to
59    /// `32 ..= 512`. `micro_steps` does not change this width:
60    /// [`Self::chunk_tokens`] absorbs it.
61    ///
62    /// The square root is the SISO rule of thumb: it balances the intra-chunk
63    /// GEMMs against the inter-chunk scan. Two dials of the block widen a chunk
64    /// without a place in this formula, and they are **not** the same widening:
65    ///
66    /// - **`mimo_rank`** (`m`) widens *both* axes of a chunk. Every rank writes
67    ///   and every rank reads, so the intra-chunk matmuls run on the fused
68    ///   `chunk_len · m`. The rule of thumb is about that product, hence the
69    ///   divisor. An unchanged `chunk_len` would cost `m²`, and this costs `m`.
70    ///   The reference gives the same advice on its `chunk_size` argument: "64
71    ///   for SISO, 64/mimo_rank for MIMO".
72    /// - **`micro_steps`** (`u`) widens only the **write** axis. All `u`
73    ///   micro-steps of a token write to the state, but the block *reads* the
74    ///   token once, at its last micro-step. So the score is
75    ///   `[batch, nchunks, heads, T·m, T·u·m]` for `T` = [`Self::chunk_tokens`],
76    ///   with `batch · sequence · heads · T · u · m²` elements. To keep that flat
77    ///   in `u`, keep `T · u` (the *folded* chunk) flat and use fewer tokens.
78    ///   Memory is the binding constraint here, because no fused kernel hides it.
79    ///
80    /// So `u` subdivides the chunk and does not shorten it, and `nchunks` grows
81    /// like `u`, not `u²`. The returned length is a multiple of `micro_steps`.
82    /// So each chunk is a whole number of tokens, and their rows are a
83    /// contiguous run. It is on the 32 grid exactly when `micro_steps` divides
84    /// it.
85    ///
86    /// `info/mamba-3/architecture-deltas.md` §8.
87    pub fn optimal_chunk_len(
88        state_rank: usize,
89        per_head_dim: usize,
90        mimo_rank: usize,
91        micro_steps: usize,
92    ) -> usize {
93        let micro_steps = micro_steps.max(1);
94        let folded = (state_rank * per_head_dim)
95            .isqrt()
96            .div_ceil(mimo_rank.max(1)) // the fused read axis is `chunk_tokens · m`.
97            .next_multiple_of(32) // rule-of-thumb: common plane dimension.
98            .clamp(32, 512); // rule-of-thumb: one plane minimum, ceiling at 512.
99        // A whole number of tokens per chunk, at (very nearly) that folded width.
100        folded.div_ceil(micro_steps) * micro_steps
101    }
102
103    /// Tokens per chunk: `chunk_len / micro_steps`, the **read** axis of the
104    /// chunk.
105    ///
106    /// `chunk_len` counts folded positions (one per micro-step). The SSD reads
107    /// each token once, at its last micro-step. So this is the row count of the
108    /// score and of the `y` that the kernels return. See
109    /// [`Self::optimal_chunk_len`].
110    ///
111    /// # Panics
112    /// If `micro_steps` does not divide `chunk_len`.
113    /// [`Self::chunk_len_or_optimal`] makes sure that it does.
114    pub fn chunk_tokens(chunk_len: usize, micro_steps: usize) -> usize {
115        let micro_steps = micro_steps.max(1);
116        assert_eq!(
117            chunk_len % micro_steps,
118            0,
119            "chunk_len {chunk_len} must be a whole number of tokens at micro_steps {micro_steps}",
120        );
121        chunk_len / micro_steps
122    }
123
124    /// The chunk length carried by this variant, if any.
125    pub fn chunk_len(&self) -> Option<usize> {
126        match self {
127            Self::Minimal(chunk_len)
128            | Self::Serial(chunk_len)
129            | Self::SerialRecalculated(chunk_len) => *chunk_len,
130        }
131    }
132
133    /// The chunk length carried by this variant, or [`Self::optimal_chunk_len`]
134    /// for the dimensions of `block` when unset. In both cases the length is
135    /// rounded **up to a multiple of `micro_steps`**, so a chunk is a whole
136    /// number of tokens.
137    ///
138    /// With that rounding, the read axis is a plain reshape. With
139    /// `chunk_len = T·u`, a chunk covers folded positions `[cL, (c+1)L)`, that
140    /// is tokens `[cT, (c+1)T)`, and the surviving rows (`≡ u−1 mod u`) are a
141    /// contiguous run of them. At `micro_steps = 1` the rounding does nothing.
142    pub fn chunk_len_or_optimal(&self, block: &Mamba3) -> usize {
143        match self.chunk_len() {
144            Some(chunk_len) => chunk_len.next_multiple_of(block.micro_steps.max(1)),
145            None => Self::optimal_chunk_len(
146                block.state_rank,
147                block.per_head_dim(),
148                block.mimo_rank,
149                block.micro_steps,
150            ),
151        }
152    }
153
154    /// Chunks per iteration of the chunk-local pass of the
155    /// [`Self::SerialRecalculated`] backward: how many chunks that pass
156    /// batches.
157    ///
158    /// The recompute backward does not need to *walk* the chunk axis. Every
159    /// chunk-local gradient (the state-to-output term and the intra-chunk
160    /// triangular term) needs only the slices of its chunk and its input
161    /// state, which the recomputed K4 already produced, batched. Only the
162    /// state gradient is a scan, and it is a few ops per chunk.
163    ///
164    /// The cost of batching the rest is memory. The score
165    /// `[batch, group, nheads, read, fused]` is live `group`-wide. At its peak
166    /// this pass holds about six score-shaped tensors, where the forward K5
167    /// holds about four at **full** width. So **half** stays under the peak
168    /// that the forward already reaches, and the walk is two iterations at any
169    /// chunk count. The bound is a ratio of live tensors, so it needs no
170    /// dimension and no absolute budget. The promise of the path (no
171    /// intermediates carried across the forward/backward boundary) holds in
172    /// both cases: when this runs, the forward intermediates are already free.
173    pub fn backward_chunk_group(nchunks: usize) -> usize {
174        nchunks.div_ceil(2).max(1)
175    }
176
177    /// The recommended default path for a given block: [`Self::SerialRecalculated`]
178    /// with [`Self::optimal_chunk_len`] for the block's dimensions.
179    pub fn default_optimal_from_block(block: &Mamba3) -> Self {
180        let chunk_len = Self::optimal_chunk_len(
181            block.state_rank,
182            block.per_head_dim(),
183            block.mimo_rank,
184            block.micro_steps,
185        );
186        Self::SerialRecalculated(Some(chunk_len))
187    }
188}
189
190impl Default for Mamba3SsdPath {
191    fn default() -> Self {
192        // Defaults to the SerialRecalculated algorithm with the optimal chunk length.
193        Self::SerialRecalculated(None)
194    }
195}
