1//! Detaching a module's parameters from the autodiff graph.
2//!
3//! Cuts gradient flow through a module. **This does not save memory** — see the
4//! warning below; [`Layers::grad_horizon`](crate::modules::Layers::grad_horizon)
5//! moves its no-grad prefix to the inner backend instead.
6//!
7//! # Why detaching the *activations* is not enough
8//!
9//! Burn tracks gradients **per tensor**, not ambiently: there is no
10//! `torch.no_grad()`. An op is untracked only when *every* input node has
11//! `Requirement::None`, so `layer.forward(x.detach())` still builds a full graph
12//! — the layer's own weights are tracked `Param`s, and one tracked input is
13//! enough. Untracked ops, by contrast, are registered with **unit state**, so no
14//! activation is retained: that is where the memory saving comes from.
15//!
16//! Cutting gradient flow through a prefix therefore takes *both* halves:
17//! [`detach_params`] on a **clone** of the module (the original keeps its
18//! tracked params, which is what lets a weight-shared layer receive gradient
19//! from its tracked applications only), and `.detach()` on every tensor entering
20//! the prefix from outside.
21//!
22//! # Warning: this frees no memory
23//!
24//! An untracked op is still **registered in the graph** — Burn keeps an
25//! `UntrackedOpsStep` per op so that a memory-bound op with an untracked parent
26//! can still retrieve it — so its output stays retained. Measured on a
27//! 64-virtual-layer `Layers<Mamba3>` (flex, `d_model` 128, batch 4, seq 512),
28//! peak RSS with a 2-layer gradient horizon was 3144 MB with a detached prefix
29//! against 208 MB with an inner-backend one, and only the latter is flat in
30//! depth. Detaching buys the gradient semantics and essentially none of the
31//! memory.
32//!
33//! # What this does *not* reach
34//!
35//! [`Module::map`] is a **no-op on plain `Tensor` fields** — Burn implements
36//! `Module for Tensor` as a constant (`map` returns `self`), so only
37//! [`Param`](burn::module::Param)-wrapped tensors go through the mapper. Weights
38//! are `Param`s and are covered; bare tensors (notably the caches) are not.
39
40use burn::module::{Module, ModuleMapper, Param};
41use burn::prelude::*;
42
43/// Clears `require_grad` and cuts the graph on every parameter it visits.
44struct DetachParams;
45
46impl ModuleMapper for DetachParams {
47    fn map_float<const D: usize>(&mut self, param: Param<Tensor<D>>) -> Param<Tensor<D>> {
48        let (id, tensor, mapper) = param.consume();
49        // `set_require_grad` fixes the *leaf* requirement (and, via
50        // `Param::from_mapped_value`, the param's own `require_grad` flag, which
51        // is re-read from the tensor); `detach` additionally re-roots the tensor
52        // so nothing upstream of it can be reached. Both are documented no-ops
53        // off the autodiff backend, so this is safe on every backend.
54        Param::from_mapped_value(id, tensor.set_require_grad(false).detach(), mapper)
55    }
56}
57
58/// Return `module` with every parameter detached from the autodiff graph.
59///
60/// Call it on a **clone**: the detached copy is what the no-grad part runs, while
61/// the original keeps the tracked parameters the back-propagated part needs.
62/// Under weight sharing both refer to the same weights, and the gradient then
63/// accumulates from the tracked applications alone.
64///
65/// A no-op in effect when the module is not on an autodiff backend — and, per the
66/// module warning, **not** a way to save memory.
67pub fn detach_params<T: Module>(module: T) -> T {
68    module.map(&mut DetachParams)
69}
