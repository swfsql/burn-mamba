1//! # burn-mamba — Mamba-1/2/3 selective state space models on Burn
2//!
3//! An experimental implementation of the
4//! [Mamba-1](https://arxiv.org/abs/2312.00752),
5//! [Mamba-2](https://arxiv.org/abs/2405.21060), and
6//! [Mamba-3](https://arxiv.org/abs/2603.15569) SSM architectures on top of the
7//! [Burn](https://github.com/tracel-ai/burn/) deep learning framework.
8//!
9//! The crate ports the official CUDA/Triton kernels to standard, portable Burn
10//! tensor operations. It has **no custom kernels**, so the same code runs on
11//! every backend (CPU, WGPU, CUDA, Metal, LibTorch, …).
12//!
13//! ## Module families
14//!
15//! Each family has its own module and supplies one
16//! [`Block`](burn_stack::modules::Block):
17//!
18//! - [`mamba1`] — the original selective SSM (conv1d + sequential selective
19//!   scan).
20//! - [`mamba2`] — Structured State Space Duality (SSD). It recasts the
21//!   recurrence as a chunkwise algorithm made of matrix multiplications.
22//! - [`mamba3`] — SSD with trapezoidal discretisation, a complex-valued state
23//!   transition (a data-dependent rotation of B/C), and MIMO rank expansion.
24//!
25//! The block-agnostic [`burn_stack`] crate holds everything around the block:
26//! the Pre-LN [`Layer`](burn_stack::modules::Layer), the (virtual-)layer
27//! [`Layers`](burn_stack::modules::Layers) stack, bidirectional pairs,
28//! latent/vocab networks, multi-gate residuals, class tokens, LR and
29//! virtual-layer schedules, and the Muon parameter groups. The [`family`]
30//! module holds `MambaBlock`, one enum over the three blocks, which selects a
31//! family at run time.
32//!
33//! ## Two execution modes
34//!
35//! Every block, layer, and network has a parallel `forward()` (training and
36//! prompt prefill) and a recurrent `step()` (token-by-token decoding). A
37//! `forward()` over a sequence equals `step()` unrolled token by token from the
38//! same initial cache. The test suites assert this parity on outputs, final
39//! cache, and gradients.
40//!
41//! ## The backend is a run-time value
42//!
43//! Burn pins the high-level `Tensor`, and so every `Module`, to its global
44//! `Dispatch` backend. So the types of this crate have no backend parameter
45//! (`Mamba2`, `Mamba2Cache`, … have no `<B>`). The `Device` of a tensor
46//! selects the backend at run time, and it also sets autodiff and the dtype.
47//! Only the internals of the custom backwards stay generic over a backend `B`.
48//! These are the primitive wrapper `F<B, D>`, the `Backward<B, _>` nodes, and
49//! the `Autodiff<B>` impls of the `…BackendExt` traits.
50
