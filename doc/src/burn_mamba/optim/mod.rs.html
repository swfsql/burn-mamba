1//! Muon support: which weights the optimizer may touch, and how the fused
2//! projections are split before it sees them.
3//!
4//! [Muon](burn::optim::Muon) replaces a 2-D weight's momentum update with the
5//! nearest orthogonal matrix (Newton–Schulz). That only makes sense for a
6//! parameter that *is* one linear map, which rules out three things in this
7//! crate:
8//!
9//! 1. **Rank ≠ 2.** Burn's `Muon::step` asserts `D == 2`, so biases, norm gains,
10//!    `dt_bias`/`D`, the Mamba-1/2 depthwise conv weight, and every MIMO/bias
11//!    3-D tensor must stay on the fallback optimizer. Passing one to Muon
12//!    panics — which is why the plan built here is an **allowlist**: only the
13//!    weights named by a [`ProjSpec`] are moved off AdamW.
14//! 2. **Embedding-like matrices.** The token embedding, the LM head, the
15//!    `LatentNetwork` input/output projections and the class-token/latent tables
16//!    are rank-2 but are lookup/readout tables at the model boundary; the usual
17//!    Muon recipe keeps them on AdamW. They are simply never listed.
18//! 3. **Fused projections.** Every family concatenates several independent maps
19//!    into one `Linear` (`in_proj` most of all). Orthogonalising that
20//!    concatenation ties together maps that share nothing but an allocation, so
21//!    the plan carries the column seams and [`Segmented`] applies Muon
22//!    **per block**. The model is untouched — the forward pass keeps its single
23//!    fused GEMM.
24//!
25//! Within a fused projection one more distinction applies: blocks that emit
26//! *per-head scalars* (Δ, `A`, `λ`) are gains rather than feature maps and stay
27//! on AdamW ([`ProjSegment::adamw`]).
28//!
29//! ## Why the 3-D tensors are not "stacked matrices"
30//!
31//! MIMO's *math* is R independent SSMs summed together, so a `[nheads,
32//! mimo_rank, per_head_dim]` tensor looks like a stack of matrices that a
33//! stack-aware Muon could take a slice at a time. It is not: the paper
34//! deliberately avoids instantiating the R maps, because that would multiply
35//! every per-head projection's parameter count by R (`DP → DPR` *per head*).
36//! Instead it keeps the SISO projection and element-wise scales its output to
37//! size R with a learnable vector (`DP + PR` per head) — in the appendix's
38//! contraction notation `X = contract(PR, P → PR)(W_X, X')`, where `P` appears
39//! in both inputs *and* the output and so is never contracted. `mimo_x`/`mimo_z`
40//! /`mimo_o` are therefore **diagonals**, and their matrix shape is a layout
41//! coincidence; orthogonalising one would constrain a set of gains. The part of
42//! MIMO that really is an R-fold matrix expansion is B/C (`DN → DNR`), which
43//! lives in `in_proj` and is already Muon's. The remaining 3-D tensors are a
44//! bias (`b_bias_hmr`/`c_bias_hmr`), an initial condition (`init_state_hpr`), or
45//! a depthwise filter (the Mamba-1/2 conv) — diagonal or embedding-like again.
46//!
47//! The seams a [`ProjSpec`] carries are therefore **per named sub-projection**,
48//! not per head/group/MIMO rank — the same boundaries the forward's
49//! `split_into` uses, and the usual Muon convention (a transformer's `W_q` goes
50//! to Muon with all heads fused). A caller who wants to test a finer split can
51//! just hand [`ProjSpec::block`] more segments.
52//!
53//! ## Usage
54//!
55//! ```ignore
56//! let plan = model_config.muon_plan();
57//! let mut optim = plan.build(&adamw_config, &muon_config);
58//! // ... then the usual `optim.step(lr, model, grads)`.
59//! ```
60//!
61//! ## Learning rate
62//!
63//! Muon and AdamW share the one learning rate `optim.step` is called with.
64//! [`AdjustLrFn::MatchRmsAdamW`](burn::optim::AdjustLrFn::MatchRmsAdamW) rescales
65//! Muon's update so its per-element RMS is `0.2·lr` — AdamW's own ballpark — so
66//! an LR schedule tuned for AdamW can be reused as-is. That is what
67//! [`muon_config`] returns; the default
68//! [`Original`](burn::optim::AdjustLrFn::Original) instead expects a Muon-specific
69//! (typically much larger) LR.

88/// The Muon defaults this crate recommends: `MatchRmsAdamW` LR adjustment, so
89/// Muon and AdamW can share one learning rate and one weight decay.
90///
91/// `weight_decay` should mirror the AdamW config's (Muon applies it after
92/// orthogonalisation, with the *unadjusted* LR).
93pub fn muon_config(weight_decay: f32) -> MuonConfig {
94    MuonConfig::new()
95        .with_adjust_lr_fn(AdjustLrFn::MatchRmsAdamW)
96        .with_weight_decay(Some(burn::optim::decay::WeightDecayConfig::new(weight_decay)))
97}

99/// Which weights Muon owns in a model, and where their fused columns split.
100///
101/// Built from a *block* config (via [`MambaBlockConfig::muon_projections`]), so
102/// it is independent of the network topology: the specs are matched as path
103/// substrings, and therefore cover a plain stack, a virtual-layer stack, and a
104/// bidirectional stack alike.
105///
106/// [`MambaBlockConfig::muon_projections`]: crate::modules::MambaBlockConfig::muon_projections
107#[derive(Clone, Debug, Default, PartialEq, Eq)]
108pub struct MuonPlan {
109    /// The fused (or plain) weights Muon may touch.
110    pub specs: Vec<ProjSpec>,
111}
112
113impl MuonPlan {
114    /// An empty plan — everything stays on the fallback optimizer.
115    pub fn empty() -> Self {
116        Self::default()
117    }
118
119    /// A plan over the given specs.
120    pub fn new(specs: Vec<ProjSpec>) -> Self {
121        Self { specs }
122    }
123
124    /// Append another plan's specs.
125    pub fn extend(mut self, other: Self) -> Self {
126        self.specs.extend(other.specs);
127        self
128    }
129
130    /// Add the [`GatedMlp`](crate::modules::GatedMlp) weights of a layer's
131    /// optional feed-forward sub-block.
132    pub fn with_mlp(self, mlp: Option<&crate::modules::GatedMlpConfig>) -> Self {
133        match mlp {
134            None => self,
135            Some(mlp) => {
136                let hidden = mlp.hidden();
137                self.extend(Self::new(vec![
138                    // fc1 fuses the SwiGLU value and gate halves.
139                    ProjSpec::path(
140                        "mlp.fc1.weight",
141                        vec![
142                            ProjSegment::muon("value", hidden),
143                            ProjSegment::muon("gate", hidden),
144                        ],
145                    ),
146                    ProjSpec::path_whole("mlp.fc2.weight", mlp.d_model),
147                ]))
148            }
149        }
150    }
151
152    /// Drop every segment named `name` from Muon's ownership (it falls back to
153    /// AdamW). Lets a caller opt a sub-projection out without rebuilding the plan.
154    pub fn without_segment(mut self, name: &str) -> Self {
155        for spec in &mut self.specs {
156            for segment in &mut spec.segments {
157                if segment.name == name {
158                    segment.muon = false;
159                }
160            }
161        }
162        self
163    }
164
165    /// Assemble the [`ModuleOptimizer`]: AdamW everywhere, Muon on the planned
166    /// weights.
167    ///
168    /// The AdamW group is the fallback (it must match everything), so any
169    /// parameter the plan does not name — every 1-D and 3-D tensor included —
170    /// keeps AdamW. `adamw`'s gradient clipping is applied to every group.
171    pub fn build(&self, adamw: &AdamWConfig, muon: &MuonConfig) -> ModuleOptimizer {
172        let mut optim = adamw.init();
173        let clipping: Option<GradientClipping> = optim.grad_clipping().cloned();
174
175        for spec in &self.specs {
176            if !spec.has_muon() {
177                continue;
178            }
179            let group = spec.param_group();
180            optim = if spec.is_whole_muon() {
181                // Unfused: stock Muon, stock state.
182                optim.with_group(group, muon.build(), clipping.clone())
183            } else {
184                optim.with_group(
185                    group,
186                    Segmented::new(spec, muon.build(), adamw.build(), 1),
187                    clipping.clone(),
188                )
189            };
190        }
191
192        optim
193    }
194}
