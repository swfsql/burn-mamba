Expand description

The interface of a block. The generic Layer and Layers call it.

Implement it once for each family (a selective SSM, a form of attention, a gated convolution, …). Then every container in this crate applies unchanged: layers, layer stacks, bidirectional pairs, latent/vocab networks, class markers, the Muon plan.

ModuleDisplay is a supertrait, so that the generic containers are themselves Modules (the derive of Burn requires it of every module-typed generic). The valid of Module lets Layers::grad_horizon move the stack to the inner backend for its untracked spans. A #[derive(Module)] block satisfies both.

Required Associated Types§

type Cache: CacheTensors

The cache of one block (the state of one layer). It is the CacheStack::Cache of Self::Caches, so it has the same CacheTensors bound.

type Caches: CacheStack<Cache = Self::Cache>

The per-network cache collection for this family.

type Options

Per-call algorithm/chunking options threaded down to Self::block_forward. () for a block with nothing to select.

Required Methods§

fn block_forward( &self, x: Tensor<3>, cache: Option<Self::Cache>, options: Self::Options, pad: Option<Tensor<2, Bool>>, ) -> (Tensor<3>, Self::Cache)

The forward: the parallel call over a window, for training and prefill.

pad ([batch, sequence], true at padding, None ⇒ no padding) is right padding: in every row, it follows all of the real tokens. A padded position is absent. The outputs of the real tokens and the returned cache are exactly those of the real tokens of the row run alone, which is step unrolled over them. The output of a padded position is unspecified. The containers keep the mask right-padded, whatever class markers they splice (see [crate::utils::padding]).

fn block_step( &self, x: Tensor<2>, cache: Option<Self::Cache>, ) -> (Tensor<2>, Self::Cache)

The step: the recurrent call over one token of each row, for decode.

fn zero_cache(&self, batch: usize, device: &Device) -> Self::Cache

The zero cache of one layer, for batch rows on device. The same cache serves forward and step. A container calls it once for each slot, so each slot has its own buffers (a captured step writes each slot in place).

fn untied_params(&self) -> Vec<UntiedParam>

The parameters that this block stores once per application of its real layer (not once), each with the axis of its copies. Empty when its config unties nothing. The BlockConfig decides which they are and tiles them. The containers run the block only through Layer::application. It narrows each one to the copy of the running application, and the containers also size the zero cache from that view. See [crate::utils::untied].

Provided Methods§

fn block_forward_packed( &self, x: Tensor<3>, cache: Option<Self::Cache>, options: Self::Options, reset: Tensor<2, Bool>, ) -> (Tensor<3>, Self::Cache)

Self::block_forward over packed rows: each row holds several segments, one after another (see [crate::utils::packing]).

reset ([batch, sequence]) is true at the first token of each segment. At that position, the block starts again from a zero cache. The positions before the first reset of a row continue from cache. The output of each segment is that of the segment run alone from a zero cache. The returned cache is that of the last segment of each row.

A block accepts a reset only at the multiples of its Self::reset_align (for example, at the start of a chunk). The caller places the resets there, and Packed::from_starts checks them. The default panics: a block that does not override it takes no packed rows.

fn reset_align(&self, options: &Self::Options) -> Option<usize>

The reset alignment of this block for options: the block accepts a reset only at a multiple of this value. None means that the block takes no packed rows, which matches the default of Self::block_forward_packed.
