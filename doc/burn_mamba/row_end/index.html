The row end: where a row reads each cache field that keeps its last samples.

Some cache fields keep the last width samples of a row, along one axis:

  • the conv window of Mamba-1 and Mamba-2 (width = conv_kernel),
  • the tap FIFO of Mamba-3 (width = lag),
  • the ln Λ and c carries of the Mamba-3 positive systems (width = 1).

A call gives these fields for the next call. Each field is the last width entries before the row end of each row, in the samples of the call after a start field:

  [ start | samples of the call ]  →  the `width` entries before the row end

start has width entries. It holds the samples from before the call, so a call that is shorter than width also gives width entries. A RowEnd does each such read of one call. The code builds it once for each call, from the padding and the resets of the call.

§Padding

Under right padding (crate::padding), the row end of a row is one past its last real position. A row with no real position reads start. Each row has its own row end. So the read is a gather at an offset for each row, with a fixed shape for all lengths.

§Resets

A packed call (crate::packing) returns the cache of the last segment of each row, and that segment starts from the origin cache. So for a row with a reset in the call, start is the origin field. Each entry from before the start of the last segment comes from start. For a row with no reset, start is the incoming field.

Let s be the first position of the last segment of a row, or 0 for a row with no reset. Let e be the row end. Then:

  • In [start | last segment], the read starts at e′ = max(e − s, 0), so its entry j < width is at i = e′ + j.
  • In [start | samples], that entry is at i for i < width (an entry of start), else at i + s.
  • With no reset, s = 0, and the read is [e, e + width) of [start | samples].

A last segment that holds only padding has e ≤ s, and its read is start: the field of the origin.

§One narrow

The gather and the cat cost memory. A read is one narrow, with no gather, when no row of the call has padding and one of these conditions is true:

  • The call has no resets.
  • width is not more than the positions of one token.

The row end of each row is then the end of the call. A segment holds at least one token of the call, so a read of one token or less stays in the last segment. A Mamba-3 read has width ≤ u, because a tap reads at most u positions back (lag ≤ u) and a positive carry reads 1. A packed Mamba-2 call still gathers. Its last segment can be shorter than conv_kernel, because a packed call requires only chunk_len ≥ conv_kernel − 1.

When the call holds at least width positions, that narrow reads the samples alone, with no cat.

In the shape suffixes of this module, w is the width of a read.
